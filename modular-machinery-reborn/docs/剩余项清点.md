### 1b. 第二类陈旧：**「旧版从来没有过」的条目**（0.26.0 补）

第 1 节审计的是「**已经做完**却仍挂在剩余项里」的条目。**另有一类同样会误导排期，而第 1 节的方法查不出它**：**旧版本身就没有实现、或根本不是一个需求类型**的东西被写成了「未移植」。它比「已完成」更隐蔽——因为它看上去确实「没有」，容易被当成欠债反复重开。

**判定规则（本方案 §6 风险登记 L673 已经写下，本次只是把它用全）**：`createRequirement` 返回 `null` 的类型**不得计入「旧版有而新版无」**。

| # | 陈旧说法 | 依据 | 现行状态 | 依据 |
|---|---|---|---|---|
| 6 | `item_durability` 需求类型未移植 | §2 M2 行 / L599 | **不是缺口**：旧版该类型 `createRequirement` 返回 `null`（`RequirementTypeItemDurability.java:12-14`），且**全仓库 `new RequirementItemDurability` 命中 0 次**，从未被构造。消耗耐久的**真实机制是 CraftTweaker 专用**的 `item` 字段 `RequirementItem.consumeDurability`（`:81/123-125/127-133/389`）+ `ItemUtils.damageAll`（`:330-363`），**没有任何 JSON 字段名**（`RequirementTypeItem.java:34-121` 不读它） | D18 / `移植方案-v2.md` §6 L673 |
| 7 | `catalyst` 需求类型未移植 | §2 M2 行 / L599 | **不是缺口**：旧版**连注册项都没有**（`RegistryRequirementTypes.java:59-75` 无 catalyst），`RequirementTypeCatalyst.java:12-14` 返回 `null`，唯一构造者是 CraftTweaker（`RecipePrimer.java:831-873`）。其真实行为是**结算路径上的永久修改器来源**（`RequirementCatalyst.java:64-86`、旧版唯一使用 `setParallelizeUnaffected` 的类型），不是需求类型 | D18 / D7 |

**结论**：这两条应从「未移植的需求类型」清单中**永久移除**，并指向 D18，避免下一个人再次把它们当成缺口勘测。**`fluid_pertick` 同样应移除**（2026-10-04 补核）：它的 `RequirementTypeFluidPerTick#createRequirement` 也**返回 `null`**（同款死类型），唯一构造者是 CraftTweaker 的 `RecipePrimer`；逐 tick 流体在旧版**没有 JSON 入口**，本版由 `fluid` + `"perTick": true` 表达且**已实现**。**保留** `gas` / `gas_pertick` 与配方适配器。⚠️ **但 `gas` 与 `gas_pertick` 不同**：`RequirementTypeGas#createRequirement` 是**活的**（读 `gas`/`amount`/`chance`，`requiresModid() = "mekanism"`），`gas_pertick` 才是死类型——所以 `gas` 是真缺口，`gas_pertick` 严格说不是。**`ingredient_array_input` 是真缺口且已于 0.26.0 完成**（D18/D19）——它与上面两条的差别正在于旧版有一个**真的**读取器（`RequirementTypeIngredientArray.java:45-143`）。
