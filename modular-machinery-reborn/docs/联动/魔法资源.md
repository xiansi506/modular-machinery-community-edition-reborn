# 魔法资源：植物魔法、自然灵气与血魔法 3（0.121.0）

支持 Minecraft 1.20.1 / Forge。安装对应模组后才注册它的仓口与需求类型；三个模组可以分别选装。接口核对版本为 Botania **1.20.1-455-FORGE**、Nature’s Aura **39.4**、Blood Magic **3.3.8-50**，还需满足各模组自身的依赖。客户端和服务端一起升级到通信协议 **13**。

本功能让自定义机器使用这些模组的资源。血之祭坛等第三方机器的配方不会自动导入。其他魔法体系继续留空。

## JEI 自然灵气绿色条

自然灵气需求在配方输入／输出区独立显示为绿色竖条。所需依赖仍是 Nature’s Aura 和 JEI，无需安装 gugu-utils。魔力、LP 与恶魔意志继续使用既有显示。

- **一次性需求**按 amount 显示总量，不随加工时间放大。
- **逐 tick 需求**按 amount × recipeTime 显示本次配方总量；悬停同时保留每 tick 数量、总量、灵气类型和脚本说明。
- 满格刻度为 **166666 原始灵气单位**，只用于显示比例，不代表环境可用量、仓口容量或加工上限。超过刻度时条形填满并显示“＋”，以悬停中的精确数值为准。
- 整条 80 像素高度均可悬停。多个需求自动换行；包含水、物品和能源时各有独立位置。

例如 amount 为 800、recipeTime 为 1200 时，一次性需求显示 800；perTick 为 true 时，总量是 960000，会显示“＋”。显示不会改变实际扣除规则、并行或修改器。此功能已离线验证，真实 JEI 画面待验收。

## 放置和连接仓口

仓口必须写入机器结构并参与成型。以下 ID 均加 `modular_machinery_reborn:` 前缀，右键打开读数界面。

| 模组 | 输入仓口 | 输出仓口 | 资源位置 |
|---|---|---|---|
| 植物魔法 | `mana_input_hatch` | `mana_output_hatch` | 仓口本地魔力缓存 |
| 自然灵气 | `aura_input_hatch` | `aura_output_hatch` | 仓口所在位置的真实环境灵气 |
| 血魔法 3 | `lifeessence_input_hatch` | `lifeessence_output_hatch` | 绑定血球的灵魂网络和本地 LP 缓存 |
| 血魔法 3 | `will_input_hatch` | `will_output_hatch` | 仓口所在区块的真实恶魔意志 |

魔力输入仓接受魔力束，仅暴露魔力接收器；魔力输出仓作为魔力池加入植物魔法网络，供功能花／发射器等按植物魔法自身规则识别与抽取。输出仓拒绝魔力束，但保留魔力池 API 的正负向传输，包括产能花直接注入魔力；配方仍按输入／输出仓的方向访问资源。提供基础火花附着接口；真实魔力束、花与火花传输组合尚待游戏验收。

默认每个魔力仓容量为 **100000**。在 `config/modular_machinery_reborn-common.toml` 中修改：

```toml
["mods.botania"]
"Mana Capacity" = 100000
```

范围 `0..2147483647`，设为 0 后无法缓存魔力。重启并让方块实体重新加载后应用容量变化。

LP 仓界面有一个血球槽，接受血魔法的 Blood Orb。先在血魔法中绑定血球；未绑定、绑定 NBT 损坏或无效血球都不能支付／接收配方 LP。输入仓每 5 tick 从血球主人的 SoulNetwork 抽取 LP，缓存目标为血球容量的 **1/10**；输出仓缓存上限为血球容量，每 5 tick 尝试存回网络。网络已满或 API 拒绝时，未存回的 LP 保留并重试。拿走血球不会删除已有缓存，重新插入有效绑定血球后才恢复配方访问。网络主人的在线状态不作为额外条件。

灵气仓和意志仓没有独立资源罐。界面显示的是环境数值：灵气条以 100 万、意志条以 100 为显示基准，这两个数不构成世界资源的硬上限。五种意志分别显示。移动仓口会改变它访问的环境；同一区块的多个仓口不能重复计算同一份资源。

## JSON 需求

把下面对象放进普通机器配方的 `requirements` 数组。`io-type` 为 `input` 或 `output`；`perTick` 默认为 `false`，设为 `true` 后每 tick 支付／生成。非逐 tick 输入在启动时支付，输出在完成时生成。

| `type` | `amount` | 额外字段 |
|---|---|---|
| `mana` | 非负整数魔力 | 无需变体 |
| `lifeessence` | 非负整数 LP | 无需变体 |
| `aura` | 非负整数 API 原始灵气单位 | 必填 `aura-type`；可选 `min-aura`、`max-aura` |
| `will` | 非负有限小数 | 可选 `will-type`、`min`、`max` |

整数单条需求最多 `2147483647`。`will-type` 默认 `default`，另有 `corrosive`、`destructive`、`vengeful`、`steadfast`，分别对应腐蚀、破坏、复仇和坚韧意志；大小写会归一化。意志输入的 `min` 表示扣除后保留量，默认 0；输出的 `max` 表示生成后允许的上限，默认 100。

`aura-type` 需匹配环境类型，例如 `naturesaura:overworld`、`naturesaura:nether`、`naturesaura:end`。灵气用 API 原始单位，**`amount: 100` 就是 100，不额外乘 100000**。`min-aura` 默认 `-2147483648`，因此允许把环境抽到负数；若要避免透支，显式写 0。`max-aura` 默认 `2147483647`。阈值也是整数，输入检查扣除后的下限，输出检查生成后的上限；错误类型或不可访问的区块不能支付资源。

以下是一份完整配方，机器 `magic_demo:combined` 及所需的物品输入／输出、魔力输入、灵气输入、LP 输入和意志输出仓必须另行定义并成型；所有模组都需安装。

```json
{
  "type": "modular_machinery_reborn:machine",
  "machine": "magic_demo:combined",
  "recipeTime": 100,
  "requirements": [
    {"type":"item","io-type":"input","item":"minecraft:cobblestone","amount":1},
    {"type":"mana","io-type":"input","amount":1000},
    {"type":"aura","io-type":"input","aura-type":"naturesaura:overworld","amount":100,"min-aura":0},
    {"type":"lifeessence","io-type":"input","amount":100},
    {"type":"will","io-type":"output","will-type":"default","amount":0.25,"max":100},
    {"type":"item","io-type":"output","item":"minecraft:stone","amount":1}
  ]
}
```

可分别安装的三个最小数据包见 [示例](../../examples/magic-resources/README.md)。它们不会随 JAR 自动加载。

## KubeJS

在 `ServerEvents.recipes` 中使用现有机器配方入口：

```js
ServerEvents.recipes(event => {
  event.recipes.modular_machinery_reborn.machine('magic_demo:combined')
    .time(100)
    .itemInput('minecraft:cobblestone', 1)
    .manaInput(1000)
    .auraInput('naturesaura:overworld', 100, 0)
    .lifeEssenceInput(100)
    .willOutput('default', 0.25, 100)
    .itemOutput('minecraft:stone', 1)
    .id('magic_demo:combined_stone')
})
```

| 方法 | 含义 |
|---|---|
| `.manaInput(amount[, perTick])` / `.manaOutput(amount[, perTick])` | 魔力 |
| `.lifeEssenceInput(amount[, perTick])` / `.lifeEssenceOutput(amount[, perTick])` | LP |
| `.auraInput(type, amount, minimum)` / `.auraOutput(type, amount, maximum)` | 一次性灵气 |
| `.auraPerTick(type, amount, io, minimum, maximum)` | 逐 tick 灵气，`io` 为 `input` / `output` |
| `.willInput(type, amount, minimum)` / `.willOutput(type, amount, maximum)` | 一次性意志 |
| `.willPerTick(type, amount, io, minimum, maximum)` | 逐 tick 意志 |

也可用 `event.custom` 写上面的完整 JSON。修改器目标新增 `mana`、`aura`、`lifeessence`、`will`；沿用并行、`parallelize-unaffected`、需求的部件选择标签、分组和逐 tick 时长补偿。整数资源先对单份修改结果向下取整，再按并行数计量。

## 扣除与验收边界

同一事务内共享真实资源身份，支付失败会回滚已执行的资源步骤；灵气回滚保留区块原有的灵气点分布。不同位置的环境范围重叠而无法安全提交时，配方会失败并回滚。极大意志余额下，小于浮点数可表达精度的支付会被拒绝，避免免费合成。

JEI 自然灵气使用绿色竖条，魔力、LP 和恶魔意志使用有颜色的文字格；各需求保留完整描述和脚本 tooltip；尚无独立魔法 ingredient 索引或 R/U 查询。界面以分段菜单数据同步双精度读数，区块更新包不包含血球的私人绑定 NBT。

离线检查使用了真实公开版本 API 和底层资源类，覆盖模拟、扣除、取消、共享资源、回滚与持久缓存；没有启动 Forge 游戏。魔力束／火花／花的实际行为、自然灵气环境效果、灵魂网络跨重启持久化、多人同步和完整 Forge 事件分派仍待实机验收。没有部署到实例、上传 GitHub、提交或推送。
