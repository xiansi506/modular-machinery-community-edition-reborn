# 能源、JEI 气体与特殊模型（0.121.0）

本轮功能已实现并完成离线检查、生产构建，尚未进游戏验收。客户端和服务端需要一起升级到当前协议 **13**，旧协议客户端不能连接。升级前备份世界；新版本保存的大于 int 的能量值不能无损降级给旧版本。

## 配置 long 能量仓

编辑 `config/modular_machinery_reborn-common.toml`。下例将微型能量仓容量设为 100 亿 FE，每次接收／抽取的上限为 50 亿 FE；默认档位数值保持不变。带点的类别名是一个 TOML 键，保留引号。

```toml
["energyhatch.size"]
TINY = 10000000000

["energyhatch.limit"]
TINY = 5000000000

[general]
enable-fluxnetworks-integration = true
```

容量范围为 `1..9223372036854775807`，传输上限为 `1..9223372036854775806`。重启世界并重新加载区块或重新放置仓口，使已有方块实体使用新配置。菜单、比较器、配方资源事务、存档与 Jade 能量仓条均读取完整 long 数值；多个仓口合计超过 long 上限时显示饱和值。

旧存档的 int 能量会完整读入，加载按保存值替换，不受传输上限限制，也不会重复累加。能量输入仓的外部接口只接受能量，输出仓只提供能量；配方仍能分别消耗输入仓、填充输出仓。

## 配方结算精度

0.118.4 中，不加修改器的 JSON `energyPerTick` 整数在 long 范围内保持原值，例如 `9007199254740993` 不会少结算 1 FE，也不再被提前限制为四分之一 long。并行／时长补偿只在最终值超过 `9223372036854775807` 时饱和；开启补偿不会改变这条边界。

修改器沿用 float 系数及先加后乘的合并规则，能源以该系数的实际值计算后向下取整。JavaScript Number 本身仍有整数精度上限；大额精确值使用 JSON 整数，普通 FE 外部接口仍受 int 限制。

## FluxNetworks 与龙之研究

### 无线能源输入／输出仓（0.122.0）

安装 **Flux Networks 1.20.1-7.2.1.15** 后，新增两族仓口，各有微型至终极八个等级。无线仓本身就是通量网络设备，不需要在旁边再放通量点或通量插头。

| 仓口 | 通量网络中的角色 | 能量流向 | 无序合成 |
|---|---|---|---|
| 无线能源输入仓 | 通量点（Point） | 网络 → 仓内缓冲 → 机器配方 | 同等级能源输入仓 + 通量点 |
| 无线能源输出仓 | 通量插头（Plug） | 机器配方 → 仓内缓冲 → 网络 | 同等级能源输出仓 + 通量插头 |

1. 把无线仓放在机器定义允许的位置。右键打开通量网络原生界面，创建或选择网络；密码、成员权限、优先级和超流模式沿用通量网络的规则。
2. 输入仓需要网络中有供能设备，输出仓需要网络中有接收设备。仓口自身不发电，也不会跨网络复制能量。网络内额度按每个仓口每 tick 合计，来自多个通量插头的输入共用该仓的额度。
3. 容量和硬件传输率沿用同等级普通能源仓的 `energyhatch.size`／`energyhatch.limit` 配置，保持完整 long 数值。界面传输限制与硬件限制取较小值；“取消传输限制”仍受硬件限制。极端 long 配置还按网络通量点数量分摊安全上限，防止多个无线仓自身的请求合计溢出。
4. 网络、设备 owner、优先级、限额及仓内能量随方块实体保存。断网保留缓冲；区块卸载或方块被移除后停止传输。拆除只掉对应等级的空仓物品，重新放置需要选网。普通 FE／long 外部接口仍按输入只收、输出只供。

创作者须把新方块加入结构定义。中型输入仓的部件示例（`size` 是方块状态，不是物品 ID）：

```json
{"x":0,"y":-1,"z":0,"elements":"modular_machinery_reborn:wireless_energy_input_hatch[size=normal]"}
```

输出仓方块 ID 为 `modular_machinery_reborn:wireless_energy_output_hatch`。物品 ID 附带等级，例如 `wireless_energy_input_hatch_normal`。原本精确指定普通能源仓的结构不会自动接受无线仓；可通过元素候选数组把两种方块列为替代。新增方块标签 `modular_machinery_reborn:energy_input_hatches`／`energy_output_hatches` 包含对应普通仓和已安装联动的无线仓。

`general.enable-fluxnetworks-integration=false` 并重启世界会停用无线入网及传输，已放置方块和本地配方缓冲保留。没安装 Flux Networks 时，不注册无线仓及其物品，不加载对应联动类或合成。原生界面的区块加载选项受 Flux Networks 配置控制；保持机器持续加工仍需要整座结构加载。刚入网尚未完成首个网络 tick 时，立即换网可能需下一 tick 再操作。

已使用真实 Flux 调度类进行离线组合验证；游戏内原生 GUI、网络密码操作、贴图效果及多人联机仍待实机验收。

按需安装对应的 **1.20.1** 模组及其依赖。没有这些模组时，普通 FE 功能继续工作。

- **FluxNetworks 普通仓接法**：把 Flux Point 连接普通能量输入仓，把 Flux Plug 连接普通能量输出仓；提供其 long 能源能力。同名配置开关默认开启，关闭后重启世界以停用该能力。无线仓可直接在自身界面选网。
- **Draconic Evolution**：提供 Brandon's Core 的 OP long 能源能力。可用输入模式的能量水晶或能量塔接收机器输出，输出模式给机器输入仓供能；具体设备方向、绑定和工作条件遵循该模组自己的设置。能量单位按 `1 FE = 1 OP` 交换。

输出仓会优先选择相邻设备的一个 long 接口，每 tick 的六面自动推出共享一个配置预算；同一个设备不会再通过 FE 接口重复收取。相邻设备只有普通 FE 时，每次 API 调用最多 `2147483647` FE。传输限制是每次调用上限，自动推出另有每 tick 合计预算；外部多次抽取不是全局每 tick 限流。

当前接口核对范围：Flux Networks 官方 1.20 分支，以及 Draconic Evolution 1.20 分支所用的 Brandon's Core `1.20.1-3.2.1.302` API。真实网络、设备与多人存读档仍需游戏验证。没有新增 IC2、GT 或其他能源后端。

## JEI 气体罐

气体配方沿用 `mekanism:oxygen` 这样的完整气体 ID，无需改变配方。安装 Mekanism 与 JEI 后，罐格读取气体自身的动画图集贴图及颜色，并显示气体罐壳；悬停保留种类、数量、逐 tick、概率与脚本提示。缺少可用贴图时回退文字。

该显示不依赖 Mekanism 的 JEI 内部 ingredient 类型，因此没有新增气体配方索引／R/U 查询能力。其他化学品也没有随本轮新增。

## 模型骨骼前缀

使用 GeckoLib 模型时，为骨骼名称添加下列前缀，大小写敏感，子骨骼继承父骨骼效果：

| 前缀 | 效果 |
|---|---|
| `emissive`、`bloom` | 全亮，并在世界模型中进入发光遮罩、双向模糊与光晕合成 |
| `transparent` | 透明混合，不写入深度 |
| `emissive_transparent`、`bloom_transparent` | 同时应用全亮、光晕与透明效果 |

透明程度来自贴图 alpha，前缀不会把不透明贴图自动变成半透明。世界光晕按真实深度遮挡，预览保留全亮／透明材质但不执行全屏光晕。每帧最多捕获 64 种发光贴图；额外贴图仍显示全亮。资源重载／断线清理待绘制数据，着色器加载失败会记录日志，并暂停光晕至资源重载，全亮效果继续保留。

光晕采用独立遮罩与场景合成，不要求额外渲染模组。**尚未实测 Embeddium／Oculus、光影包、Fabulous 模式、窗口缩放和资源重载画面**。本轮没有移植异步 VBO 或其他外部模型加载器。
