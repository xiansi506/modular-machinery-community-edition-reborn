# 气动工艺与余烬（0.121.0）

适用于 Minecraft 1.20.1 / Forge / Java 17。气动工艺对接 **PneumaticCraft: Repressurized 6.0.23**；余烬对接 [RCXcrafter 的 Embers Rekindled](https://github.com/RCXcrafter/EmbersRekindled)，核对版本为 **1.20.1-1.4.7**。二者分别选装，满足各自依赖。客户端和服务端均使用 Reborn 0.121.5、协议 **12**。

## 仓口和实际资源

所有 ID 均加 `modular_machinery_reborn:` 前缀，仓口要写进机器 `parts` 并成型。

| 模组 | 输入仓 | 输出仓 | 资源 |
|---|---|---|---|
| 气动工艺 | `compressed_air_input_hatch` | `compressed_air_output_hatch` | 原生 tier-two 空气处理器，连接气动管道 |
| 余烬复刻版 | `ember_input_hatch` | `ember_output_hatch` | 真实 Ember capability 缓存，支持小数 |

气动仓默认容积 **16000 mL**。空气量 = 压力（bar）× 容积（mL），不是普通流体，不放进流体仓或 Mekanism 气体仓。处理器负责管道均压、负压和超压行为。机器产气按危险压力上限检查空间；外部供气仍遵循气动工艺的原生危险／临界压力规则。未连接管道的输出仓会向上漏气。右键界面显示空气量、压力、有效容积及压力限值。

余烬仓默认容量 **256000 Ember**。将余烬接收器贴在仓口上，通过复刻版正常的发射／接收链路供能。输出仓中的能量可由复刻版的发射器抽取。余烬能量不转换成 FE。API 传输支持模拟，不足时只接收实际能容纳的量。

通用配置：

```toml
["mods.pneumaticcraft"]
"Air Volume" = 16000

["mods.embers"]
"Ember Capacity" = 256000.0
```

0.121.5起，余烬后端在一次方块实体生命周期内固定服务端容量，配置变化不会在扣款或回滚中途隐式夹掉库存；新后端才采用新容量，客户端以同步容量显示。修改后重启并重新加载方块实体。新值约束后续仓口；余烬读档会按当前容量夹取，降低容量前先排空。气动仓容积使用当前配置，存档中的空气量按原生处理器加载，改容积会改变压力。不要在运行中的机器上直接修改容量。

## JSON 配方需求

下列均为 `requirements` 的元素，完整机器和配方见 [教学包](../../examples/pneumatic-embers/README.md)。

一次性输入：开工时要求至少 4.5 bar，并扣除 1000 mL 空气。

```json
{ "type": "compressed_air", "io-type": "input", "pressure": 4.5, "air": 1000 }
```

压力是**扣费前**的仓口条件，不随并行倍增。1000 mL 扣除后压力可能低于 4.5 bar，不会因为本次扣费结果降低而撤销这次已支付输入。若要持续维持压力，使用逐 tick 需求：

```json
{ "type": "compressed_air_pertick", "io-type": "input", "pressure": 4.5, "air": 10 }
```

每个成功结算 tick 检查压力并扣 10 mL；100 tick 单并行、无修改器的基础用量是 1000 mL。供气不足会按机器现有失败策略暂停／失败。`air: 0` 只检查压力，输入省略 `air` 同样表示只检查压力。输入 `pressure` 必填，单位 bar；0 不设压力门槛，负数要求达到对应真空，例如 -0.5 表示压力 ≤ -0.5 bar。

输出按完工一次性产生，或使用 `compressed_air_pertick` 逐 tick 产生：

```json
{ "type": "compressed_air", "io-type": "output", "air": 1000 }
```

`air` 为 0～2147483647 的整数，输出必须声明数量。也接受数量别名 `amount`；新内容推荐写 `air`。旧 `time` 字段仅保留正整数兼容读取，实际加工时长和 JEI 总量按根 `recipeTime` 计算。`perTick` 如显式填写，必须与类型一致；不使用 `compressed_air` 加 `perTick:true` 替代逐 tick 类型。

余烬输入／输出：

```json
{ "type": "ember", "io-type": "input", "amount": 100.5 }
```

`amount` 是非负有限数，允许小数；也接受旧 `ember` 数量字段。默认一次性，`perTick:true` 表示每个成功 tick 的数量。输出改为 `io-type:"output"`，需余烬输出仓和空间。

两类资源支持 `selector-tag`、并行、`parallelize-unaffected` 和共享资源事务。空气数量随并行放大，压力条件保持原值；余烬按小数结算。修改器目标分别为 `compressed_air` 和 `ember`。多条需求访问同一缓存时共享剩余量；后续提交失败会回滚已提交的资源。气动与余烬仓口不单独分输入组；物品和流体的输入组规则照常生效。

## KubeJS 6

接在 `event.recipes.modular_machinery_reborn.machine('机器 ID')` 后：

```text
// 一次性 1000 mL，开工压力至少 4.5 bar。
.compressedAirInput(4.5, 1000)
// 每 tick 10 mL，且每 tick 要求至少 4.5 bar。
.compressedAirPerTick(4.5, 10, 'input')
// 一次性输出 1000 mL。
.compressedAirOutput(1000)
// 逐 tick 输出空气时 pressure 参数传 0。
.compressedAirPerTick(0, 10, 'output')
// 默认一次性；第二参数 true 为逐 tick。
.emberInput(100.5)
.emberOutput(0.25, true)
```

这是方法链片段，不能单独保存运行。完整 JSON／KubeJS 替代示例见教学包，只安装其中一种定义。

## JEI 与验证边界

压缩空气和余烬占各自输入／输出侧的资源格，分别显示蓝色／橙色条和资源名称。悬停查看准确数量、逐 tick 标识、压力条件及脚本说明。条形比例只是显示，不代表当前仓口可用量，实际容量以仓口界面和配置为准。

离线检查与构建结果以 [更新记录](../归档/版本记录/更新记录-0.119.0.md) 为准。真实管道均压、输出仓泄漏／超压、余烬发射接收链路、多人同步和 OpenGL 画面需在游戏中验收；不能把离线接口测试当成完整实机通过。
