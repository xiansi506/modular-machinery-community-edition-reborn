## 2. 原料列表 `IngredientList` 的精确规格

出处：`.../widget/impl/preview/IngredientList.java`（93 行）

```java
public static final int MAX_STACK_PER_ROW = 9;      // :19
public IngredientList() { setWidthHeight(174, 36); } // :24  ← 174 宽、36 高
```

- **每行 9 格**（`MAX_STACK_PER_ROW = 9`），**36 高 = 2 行**（每格 18 像素）。
- 槽位贴图取自 widget 图集：`TextureProperties.of(WIDGETS_TEX_LOCATION, 184, 194)`（`:60`、`:72`）。
- **超出容量靠滚动**，不是丢弃：它是个 `ScrollingColumn`，滚动条 `setMargin(3,1,1,1)`、`setWidthHeight(8,34)`、
  滑块 8×13（`:36-44`），贴图自 widget 图集 (184/194/204/214, 143)。滚动单位 = 总范围 / 5（`:30`）。
- 内容 = **物品列表 + 流体列表**串接（`:51-83`），两者用同一套槽位。
- 顺序：先物品后流体；每满 9 格换行（最后一行不满也换行）。

> 我方文档早先写的「成分列表在 (5,179)」是对的，但**尺寸 36 高、每行 9 格、可滚动**这三点容易漏——
> 只画一行 18 高、并在 y=205 放机器名，会**正好压在原版第二行的位置上**。

## 5. JEI 页面与游戏内界面共用同一面板

出处：`.../preivew/PreviewPanels.java`（40 行）、`.../gui/integration/GuiBlueprintScreenJEI.java`（64 行）

- 两个入口都调 `PreviewPanels.getPanel(machine, widgetGui)`，**面板与按钮完全一致**。
- 游戏内界面：`GuiScreenBlueprint`（184×220，贴图 `guiblueprint_new.png`，`doesGuiPauseGame() == false`）。
- JEI 页面：`CategoryStructurePreview` 背景取 `guiblueprint_new.png` 的 (0,0,184,220)（`:40`），
  标题 `jei.category.preview` = **「结构预览」**；
  并把机器的成分注册为**隐藏**槽位（`group.init(n, ..., -999999, -999999)` `:73`、`:76`，最多 81 个输入）
  以便 JEI 索引——即**原版 JEI 里成分是不可见的**，可见的成分网格由面板自己画。

> ⚠️ 因此「JEI 底部原料」在原版里是**面板画的可视网格**；JEI 的真正槽位是隐藏的、只供搜索。
> 若改成真实 JEI 槽位（可悬停、可聚焦），那是**优于原版**的做法，但**与原版行为不同**，文档里要写清楚。

## 6. 复刻优先级建议（按「与原版差距 × 实现成本」）

1. **布局对齐**（成本最低、差距最明显）：原料列表改 **174×36（2 行 × 9 格）**、标题移到 **(5,5)** 且显示
   前缀+机器名、视口 **(6,26) 172×150**。当前视口 y 已是 26 ✓，`NAME_Y` 已上移 ✓，但**列表仍是单行 18 高、宽 172**。
2. **机器信息**（现在就能算）：长/高/宽、控制器 Y 位置、是否需要蓝图、是否存在动态结构。
3. **重置中心**（便宜）：复位拖动/缩放——你们已经加了 `panX/panY`，缺一个复位入口。
4. **片式（逐层）预览 + 滚动条**：数据现成（`StructurePreview` 的方块按 Y 分组即可）。
5. **循环替换方块**：数据现成（`MachinePattern.positions()` 的 `List<BlockMatcher>` 就是每个位置的可用方块），
   原版是每 1.5 秒轮换。
6. **投影到世界**（成本高，独立系统）：`gui.blueprint.popout.*` 那一套。
7. **升级列表高亮 / 动态结构 ± / 成型切换**：依赖 M6 与动态结构，**先不做**。
