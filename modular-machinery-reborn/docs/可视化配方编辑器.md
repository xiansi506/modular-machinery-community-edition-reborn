## 最快用法

1. 在 MMCER 创造栏取得 **配方编辑器**，或 `/give @s modular_machinery_reborn:recipe_editor`。右键打开；对机器控制器使用会自动选择其绑定、已成型或蓝图对应机器。也可用面板按钮按名称选择机器。
2. 左侧放输入、右侧放输出：点空格搜索物品，或从 JEI 拖入物品、流体、气体。材料只是虚拟配方内容，不消耗背包物品。
3. 滚轮改数量，Shift＋滚轮一次改 10；右键删除，左键进入详情。其他资源从各栏的“其他”按钮添加。材料较多时用栏顶箭头翻页。
4. 填写**秒数**和 **FE/t 能耗**，点“下一步：检查配方”，确认预览后“保存配方文件”。0.05 秒＝1 tick；能耗 0 或留空表示不耗能。含标签等高级条件的能源需求会单独保留，不能被快捷输入覆盖。

配方 ID 已自动生成，需要自定义 ID、并行、概率、NBT、KubeJS 或原文时再打开“高级编辑”。搜索同时支持本地化名称和注册 ID。原高级表单与命令入口保留。

**保存不会自动安装或重载。** 文件仍在服务端 `config/modular_machinery_reborn/exports/recipes/`。安装 JSON 时按预览中给出的配方 ID 放入对应数据包路径；MMCER 命名空间的配方也可按下文安装到配置 recipes 目录。不要把时间戳导出名直接当作配方 ID。关闭仍会结束草稿会话，需要保留原文时先在高级原文页复制。

下面的详细操作属于高级编辑模式。

# 可视化配方编辑器

适用 **0.123.0 / Minecraft 1.20.1 / Forge / Java 17，通信协议 13**。客户端和服务端需要同时更新。编辑器首版已实现；真实游戏的输入、拖拽、布局和多人网络仍待验收。

## 打开与基本操作

在创造模式、权限等级至少 2 的玩家身份执行 `/mm-recipe_editor`，也可以执行 `/mm-recipe_editor "命名空间:机器"`。控制台无法打开玩家界面。不需要手持建造选择工具。

1. 在“配方”页填写完整配方 ID（如 `pack:smelting/iron`），选择服务端已经加载的机器。机器列表最多显示 512 项，其他机器可直接填写 ID。多个归属机器可以在机器输入框中写 JSON 字符串数组。
2. 填写时长，**20 tick = 1 秒**。并行上限留空沿用机器设置；填写数值只限制这条配方，不会提升机器的并行能力。
3. 在“需求”页添加输入与输出，用上一项／下一项切换需求。“参数页”在基础资源、常用选项、物品 NBT 三页之间切换。选择新资源类型会用该类型默认值替换当前需求，请先复制需要保留的内容。
4. 选择 JSON 或 KubeJS 格式，点击“校验并预览”。检查资源方向、数量、基础总量、仓口提示与导出代码，再点击“确认导出”。任何草稿变更都需要重新校验。

编辑器不会自动安装配方或执行 `/reload`。关闭编辑器会结束服务端草稿会话；离开维度、重生、退出和停服也会清理会话。**关闭前在“原文”页复制草稿**；首版没有跨会话草稿库或编辑撤销历史。

## 材料选择与资源单位

JEI 可用时，在对应需求的基础参数页，将物品、流体或 Mekanism 气体拖到注册 ID 输入框；只提供虚拟材料，不消耗玩家物品。物品会带入完整、有类型的 NBT；流体／气体拖入提供资源 ID，数量仍以表单为准。主手读取按钮同样只读取物品 ID 和 NBT，不复制整组数量。

没有 JEI 也能填写完整 ID。物品、物品标签、流体、灵气类型和意志类型可以打开检索列表，输入 ID 片段后明确选择结果。气体支持 JEI 拖入或直接填写完整注册 ID。标签输入使用 `#forge:...`，输出应选择具体物品。

| 类型 | 数量单位 | 结算方式与注意事项 |
|---|---|---|
| 物品 `item` | 个，正整数 | 输入固定数量；输出可填 minAmount / maxAmount 范围 |
| 流体 `fluid` | mB，正整数 | 可选每 tick |
| 气体 `gas` / `gas_pertick` | mB，正整数 | 需要 Mekanism；逐 tick 会使用对应类型 |
| 能源 `energy` | FE/t，非负 long | 始终每 tick；支持 9223372036854775807 上限 |
| 魔力 `mana` | 原始 Mana，非负 int | 需要 Botania，可选每 tick |
| 灵气 `aura` | 原始 Aura，非负 int | 需要 Nature’s Aura，必填 aura-type；下限默认允许负环境量 |
| 生命源质 `lifeessence` | LP，非负 int | 需要 Blood Magic 3，可选每 tick |
| 意志 `will` | 非负有限小数 | 需要 Blood Magic 3；填写意志变种和资源上下限 |
| 压缩空气 `compressed_air` / `_pertick` | mL，非负 int | 需要 PneumaticCraft；压力用 bar，是独立条件，负值表示真空条件 |
| 余烬 `ember` | 非负有限小数 | 需要指定的 Embers Rekindled 复刻版，可选每 tick |

数量选择与资源类型的规则沿用[配方指南](KJS-配方指南.md)、[魔法资源](联动/魔法资源.md)和[气动工艺与余烬](联动/气动工艺与余烬.md)。缺少依赖的资源类型标 `*`；服务端校验会拒绝缺少依赖的配方。

物品、流体和气体的 `chance` 是 **0～1**，留空表示 1。“不随并行放大”会写入 `parallelize-unaffected`；仓口标签会写入 `selector-tag`。输入物品不要填写不同的最少／最多数量。NBT 显示覆盖需要同时设置匹配 NBT，无额外匹配条件时可使用 `{}`。

## NBT 与高级字段

物品 NBT 支持已有的 JSON 模板，例如 `{"Damage": ">=5"}`；模板字符串仍按项目已有的数字／比较／正则语义解析。手持物品和 JEI 导入使用 `["mmr:literal_nbt_v1", "<SNBT>"]`，保留数字类型、数组、文本及类似数字的字符串。这种 literal 数组现在也可用于物品需求的 `nbt` 和 `nbt-display`。不要把这两种格式混淆。

“原文”页可粘贴完整配方 JSON，再切回表单编辑常用字段。表单在原 JSON 的副本上修改，保留命令、脚本、触发器、修改器、复杂原料与其他未表示字段。高级需求通过原文编辑，表单不会猜测其资源数量。原文语法或表单数值错误时保留输入并报告错误，修正后再切页。更改配方类型会被校验拒绝。

首版限制：每份草稿最多 64 条需求；JSON 最多 16000 个 Java 字符／24000 个 UTF-8 字节、嵌套深度 64；格式化导出最多 65536 个字符。超限会拒绝校验，适合在外部文本编辑器中维护的大型配方不需要经过此工具。

## 预览、校验与安装

服务端使用正式 `MachineSerializer` 和需求解析器检查配方，并核对机器关联、依赖模组、整数范围及常见误用。物品图标仅展示第一行可容纳的条目，完整需求在文字预览和原文中。文字列出方向、单位、每 tick／每次、概率、标签、压力和基础用量；**总量按单次、无修改的基础配方计算**，不是实际运行的消耗承诺。脚本、随机概率、输出范围、触发时间、修改器与实际并行都可能改变结果。

仓口和 selector-tag 提示只对基础结构做启发式检查，不会阻止有自定义／动态端口的作者导出，也不能代替实际成型、能源供应、标签可见性和加工验收。表单之外的未知字段会保留；保留不代表引擎支持该字段。

文件写在**服务端** `config/modular_machinery_reborn/exports/recipes/`，使用时间戳文件名，重名追加编号，永不覆盖已有文件。客户端不能指定任意服务器路径。导出前会重新校验当前注册表；机器被重载移除时旧预览不能直接保存。磁盘失败保留已校验草稿，成功后需要重新校验才能再次导出。

- **JSON 数据包**：将导出文件重命名并放入 `data/<namespace>/recipes/<path>.json`。例如 `pack:smelting/iron` 对应 `data/pack/recipes/smelting/iron.json`，数据包根需要 `pack.mcmeta`，1.20.1 的 `pack_format` 为 15。导出目录本身不是数据包。
- **配置目录**：仅对 `modular_machinery_reborn:<path>` ID，文件可以安装到 `config/modular_machinery_reborn/recipes/<path>.json`，因为这个来源使用固定命名空间。不要以时间戳文件名直接安装后还期望 ID 不变。
- **KubeJS**：将 `.js` 放入 `kubejs/server_scripts/`，保留生成的 `.id(...)`。脚本通过 Java Gson 解析 JSON 字符串，避免 JavaScript Number 把超出 2^53 的能源值舍入；需要安装 KubeJS 及其依赖。对应的原生 `event.custom(...)` 必填机器字段初始化也已修复。

两种等价导出只安装一种。确认 ID 没有冲突、在途加工结束后 `/reload`，使用 `/mm-syntax` 检查定义关联，再实际运行一次加工和必要的逐 tick／并行用例。
