# Modular Machinery：Community Edition Reborn 移植计划

目标平台：Minecraft 1.20.1、Forge 47.2.0、Java 17  
项目目录：`C:\Users\kk07H\Desktop\模组\modular-machinery-reborn`  
旧版参考：`C:\Users\kk07H\Desktop\模组\_mmce-src\ModularMachinery-Community-Edition-master`

## 总体原则

本项目不是把 1.12.2 的 Cleanroom/Forge API 逐行改名，而是保留旧版的玩法概念，在 1.20.1 Forge 中重新实现注册、数据、能力、菜单和客户端渲染。机器配方以原生数据包为基础，并提供 KubeJS 入口；每个阶段都要能构建、启动并留下迁移日志。

## 阶段 0：盘点与可构建基线

状态：已完成。

- 固定 Mod ID、版本号、Forge/Java 版本和 Gradle 离线构建方式。
- 解压旧版源码，记录旧版注册名、纹理名、模型、语言文件和 GUI 资源。
- 建立 `迁移日志.md`，每个可交付版本记录变更和 SHA-256。
- 验收：`./gradlew.bat build --offline --no-daemon` 成功，能生成可加载的 Forge JAR。

## 阶段 1：注册表、资源和本地化

状态：基础部分已完成，仍需持续补齐旧版内容。

- 注册控制器、基础输入/输出/能源/流体仓口和旧版独立物品。
- 注册 tiny、small、normal、reinforced、big、huge、ultimate、ludicrous 等等级仓口；流体额外包含 vacuum。
- 将旧版 16×16 贴图迁移到 `assets/modular_machinery_reborn/textures`，为每个方块生成 blockstate、block model 和 item model。
- 维护 `en_us.json`、`zh_cn.json`，名称必须包含仓口类型和等级。
- 验收：创造模式物品栏能找到所有注册对象，资源包日志没有缺失纹理；每个模型引用的 PNG 都存在。
- 注意：旧版没有单独的物品终极 overlay，目前终极物品仓使用旧版荒谬级完整贴图作为兼容资源，后续如找到正式素材再替换。

## 阶段 2：控制器与多方块结构

状态：第一版已完成，功能仍需扩展。

- 控制器保存水平 `FACING`，放置后模型正面朝向玩家。
- 第一版结构是控制器同一 Y 层周围 3×3 环的八个方块。
- 当前结构方块接受铁块和四种基础仓口；结构检查集中在 `MachineStructure`，后续应改为等级仓口和端口类型统一判定。
- 后续扩展：支持旧版完整多方块尺寸、层级、方向旋转、结构预览和结构错误提示。
- 验收：四个水平朝向都能正确显示正面；结构形成/失效会同步到 GUI 和机器处理逻辑。

## 阶段 3：真实物品、能源和流体通道

状态：控制器内部能力已完成，仓口外部路由未完成。

- 控制器方块实体已经提供 Forge item、FE、fluid capability，并按配方持续处理。
- 目前 GUI 的两个物品槽属于控制器内部槽位；`MachineHatchBlock` 还是可见端口方块，没有独立方块实体和能力路由。
- 下一步为仓口增加独立 BlockEntity 或统一端口能力：物品输入/输出、FE 输入/输出、流体输入/输出，并让控制器按结构收集这些端口。
- 修复能源和流体的持久化、容量按等级变化、输入输出方向和满仓回退逻辑。
- 验收：从外部管道/能源网/流体网输入后，机器能消耗真实资源；输出不能凭空丢失；世界重载后库存、能源、流体保持。

## 阶段 4：GUI、菜单和 JEI

状态：第一版已完成，仍需随能力系统扩展。

- 菜单通过 `ContainerData` 同步进度、最大进度、能源百分比和结构状态。
- JEI 已列出机器配方；后续应加入物品/能源/流体输入输出、仓口等级和结构说明。
- 后续扩展流体槽、能源容量、配方缺少材料提示、鼠标悬停说明和更完整的中文文本。
- 验收：客户端打开 GUI 不出现错位/黑紫纹理；断开重连后数据显示正确；JEI 配方可查看并与实际处理结果一致。
