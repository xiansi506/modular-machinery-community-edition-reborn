# 小数并行搜索契约（0.121.85）

WILL与EMBER沿用配方名义价格、补偿顺序和既有真实移动精度；余额没有实际变化不会被当作已支付。某些单份成本太小，但合成多份后可以表示，所以“单份不能开工”不再自动淘汰可付多份。

| 范围 | 行为 |
|---|---|
| 完整上限实际可付 | 返回该上限，它就是最高候选 |
| 有限小范围 | 完整共享枚举，恢复原需求份数，不写实仓 |
| 已声明纯线性容量规划，且同一身份在该阶段单向、整个共同二次幂格点在53位精确范围内 | 完整共享单调二分，支持零余额输出及精确多端口分仓 |
| 已声明量子的原生端口，保守包络能证明必要格点 | 精确整数余数窗口跳过不可能候选，保留完整真实付款检查 |
| 多端口/别名共享 | 按实际身份与阶段合并包络；只有可证明首个端口完整承担时取必要格点；不同身份可联合约束 |
| 需要复杂分仓截断、未知planner/需求，或证明/枚举超预算 | 明确搜索未完成；拒绝新付款，不回退1份，不丢已付批次 |

附属模组可通过MagicPort.Access的`parallelQuantum(lowerBalance, upperBalance)`声明量子：闭区间内该planner的每个真实候选余额差必须是返回的正二次幂量子的整数倍；查询必须纯只读，身份、余额和快照一致性必须可靠。默认NaN表示未知，不能为“让配方运行”随意返回一个更粗量子。自定义plan必须维持声明；源发生变化就不能沿用旧证明。普通JSON/KubeJS作者不需填写此接口。

`linearParallelPlanning()`另声明该planner只有纯候选余额容量/阈值规则，没有随请求量变化的自定义权限或副作用。默认false；原生WILL/EMBER接入。它本身不证明单调，仍须通过共同格点、53位幅度和单IO方向检查；混合方向、跨精度边界仍走完整有限枚举或必要格点路径。

候选价格的double乘法舍入及原有movementMatches容差已计入必要窗口，量子只用于排除不可能候选，不用于修改价格。实际结算仍检查全部共享需求、容量、权限与真实余额变化。格点提示也不授予未知能力恢复权限，另见[资源事务契约](资源事务契约.md)。

算法最多4096候选/跳转迭代，需求加权工作不超过65536，整数floor-sum证明另共用65536步预算；超出只表示未完成，不表示没有合法解。此支持契约不承诺任意复杂自定义planner或任意规模可完成精确搜索。
