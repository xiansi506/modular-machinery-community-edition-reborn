# 资源事务契约（0.121.84）

本页面向附属模组Java开发者。普通JSON/KubeJS配方无需声明这些接口；自有仓口、ME缓冲及当前自定义资源后端由模组接入。

| 对象 | 候选写入规则 | 失败后恢复 |
|---|---|---|
| 精确原生ItemStackHandler、FluidTank、EnergyStorage实例 | 原生容量/类型与传输限制 | 已知原生状态恢复 |
| 自有物品仓、流体仓、ME手动/九罐池 | NativeItems/NativeTank或CandidateItems/Fluids | SnapshotParticipant |
| 自有LongEnergyStorage | long容量/速率 | 直接恢复long状态 |
| 外部物品/流体/能源能力 | 相应CandidateItems/Fluids/Energy加SnapshotParticipant | 必须显式承诺完整本地快照恢复 |
| 外部OpaquePort、自定义MagicPort.Access | 其显式transactionView/plan实现 | 实现负责自己的共享规划、权限与恢复 |
| 仅Forge可变接口、仅Candidate接口、任意未声明子类 | 事务写入拒绝 | 不尝试猜测逆向退款 |
| 仓口自动推能目标 | 精确原生EnergyStorage或TransferAccounting收据；自有方向壳/long仓已接入 | 仅已证明本次未接收额度退回源 |

SnapshotParticipant包含`transactionSnapshot()`、`transactionUnchanged(snapshot)`、`transactionRestore(snapshot)`；快照须独立保存全部相关资源、候选权限/版本状态，一致性检查必须纯只读。恢复必须绕过正常插入/提取门槛，覆盖部分写入和执行抛错，不做不可逆外部IO；所有外部修改须与提交串行。不能因有set方法就自动认为安全。NativeItems/NativeTank的子类若引入额外权限、计数配额或状态，也须相应扩展候选/快照契约，不能只继承一个名字。

CandidateItems的插入检查会收到候选槽当前内容，提取检查会收到候选槽与请求量。CandidateFluids收到候选各罐内容；CandidateEnergy收到候选储量。不得以实仓旧内容代替候选状态；返回允许数量后，事务仍检查原生容量/类型，提交时实际操作仍可拒绝，并由快照恢复。工具/容器替换同时检查提取和候选空槽插入权限。

TransferAccounting的`transferSnapshot()`和`receivedSince(snapshot)`须仅报告本次接收的确定额度，包含执行写入后抛错的部分；任意余额差并不自动满足该契约。收据非法、外部状态在提交期间变化或契约违约时仍可能需要人工排查，模组不会盲退款或覆盖新值。

安全策略会降低无契约第三方能力的直接兼容性。外部模组主动调用仓口FE/long接口仍可工作；本策略只约束MMCER自身组织的事务写入和自动推能。不要为获得兼容性而随意给远端网络、不可逆设备或可并发对象加标记。
