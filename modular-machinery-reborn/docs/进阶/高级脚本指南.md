# 高级脚本指南（0.121.11）

适用于 Minecraft 1.20.1、Forge、KubeJS 6。脚本放在 `kubejs/server_scripts/`；修改后执行 `/reload`。基础机器与配方写法见 [配方指南](../KJS-配方指南.md)。当前通信协议为 **12**，服务器与客户端须同时更新。

客户端 GUI 信息、模型选择和动画使用独立的 `client_scripts` 入口，见 [客户端脚本指南](客户端脚本指南.md)。

0.121.8 起，全局 `MachineLifecycleEvents.recipeCheck` 回调抛错会拒绝开工；普通与工厂的逐 tick 回调抛错会暂停推进。START 发生在每 tick 资源支付前，END 发生在支付后，END 抛错不返还该 tick 已扣资源。KubeJS 日志保留具体异常，修正并重载脚本后可重试。通知类回调没有通用回滚能力，脚本已经主动执行的世界修改也不会自动撤销。

0.121.11 起，最后一 tick 与结束需求共用虚拟容量检查；若最后一 tick 已成功推进并支付，结束结算暂时失败时只重试结束阶段，存档也保留该状态。此时不会重放逐 tick 回调或处理命令；最终完成事件与完成命令只在实际结束成功后触发。END 回调主动阻止进度仍遵守原有规则：该 tick 已付、进度不增加，下次仍需尝试该 tick。

## 机器定义与专属回调

```js
MachineRegistryEvents.registry(event => {
  event.machine('kubejs:quality_press')
    .localizedName('精密压机')
    .part(1, 0, 0, 'modular_machinery_reborn:item_input_hatch')
    .selectorTag('feed')
    .part(-1, 0, 0, 'modular_machinery_reborn:item_output_hatch')
    .color(0x86b7cf)
    .hideComponentsWhenFormed(true)
    .on('recipeCheck', e => {
      if (e.controller.customData.getInt('heat') < 100) {
        e.setFailed('温度不足 100')
      }
    })
    .register()
})
```

`.selectorTag()`、`.nbt()`、`.previewNBT()`、`.blockChecker()` 修饰最近一个 `part()`／`parts()`。坐标数组展开后，每个位置都保留条件，旋转、合并和动态结构也保留它们。

```js
// 放在机器定义的方法链中；以已有箱子方块为例。
// .part(0, 1, 0, 'minecraft:chest')
// .nbt({ Lock: 'factory_key' })
// .blockChecker((world, pos, state, nbt) => nbt.getString('Lock') === 'factory_key')
```

方块检查器接收世界、绝对坐标、方块状态和 NBT 副本；不加载尚未加载的区块。NBT 匹配使用与配方相同的比较规则。`previewNBT()` 为蓝图／JEI 的预览方块实体提供具体数据，结构匹配仍由 `nbt()`／检查器决定。

机器还提供 `.dynamicPattern(object)`、`.controllerBoundingBox(array)`，以及 `.field(key, value)`。`field()` 仍经过机器 schema 校验；动态结构的对象格式与 JSON 一致。

## 结构预览 NBT（0.112.0）

下面是一台只有展示结构的机器：

```js
MachineRegistryEvents.registry(event => {
  event.machine('kubejs:banner_preview')
    .localizedName('旗帜预览')
    .part(1, 0, 0, 'minecraft:white_banner[rotation=0]')
    .previewNBT({ Patterns: [{ Pattern: 'bs', Color: 14 }] })
    .register()
})
```

蓝图／JEI 会显示底部带红色横条的白旗帜。JSON 机器可在对应 part 中写同样的对象：

```json
{
  "x": 1, "y": 0, "z": 0,
  "elements": "minecraft:white_banner[rotation=0]",
  "preview-nbt": {"Patterns": [{"Pattern": "bs", "Color": 14}]}
}
```

显示 NBT 的字符串按字面读取，告示牌的 JSON 文本和名称字符串不作为正则。普通数字／布尔可以直接写；需要指定 NBT 数值类型时，用 `"0b"`、`"3s"`、`"1000l"`、`"1.5f"` 等字符串。允许空字符串、空列表与空对象；同一列表仍须保持统一 NBT 类型。结构匹配用的 `nbt()` 继续使用原有字符串／正则与数值比较规则。

场景根据当前候选方块创建实体，NBT 中的 `id/x/y/z` 不会替换实体类型或预览坐标。预览不执行方块实体逻辑 tick，不打开容器，不改变实际世界；需要 `lit`、朝向等方块状态时，在 `elements` 中明确指定。坏数据或第三方渲染异常会记录日志并退回普通方块显示。世界投影仪继续使用方块模型。

箱子、旗帜、告示牌的完整 JSON／KubeJS 文件见 [预览 NBT 示例](../../examples/preview-nbt/README.md)。生产实体和渲染分派已离线验证，实际 OpenGL 画面与第三方模组效果仍待游戏验收。

## 物品检查与改写

```js
ServerEvents.recipes(event => {
  event.recipes.modular_machinery_reborn.machine('kubejs:quality_press')
    .time(100)
    .itemInput('minecraft:iron_ingot', 2)
    .selectorTag('feed')
    .itemChecker((controller, stack) => {
      const tag = stack.getTag()
      return tag !== null && tag.getInt('quality') >= 2
    })
    .requirementTooltip('需要 quality 至少为 2 的铁锭')
    .itemOutput('minecraft:gold_ingot', 1)
    .itemModifier((controller, stack) => {
      stack.getOrCreateTag().putInt('batch', controller.customData.getInt('batch'))
      return stack
    })
    .on('recipeStart', e => {
      const data = e.controller.customData
      data.putInt('batch', data.getInt('batch') + 1)
    })
    .tooltip('精密压制产物会记录批次')
    .id('kubejs:quality_press_gold')
})
```

`itemChecker()` 和 `itemModifier()` 作用于最近一条物品需求。检查器返回布尔；改写器必须返回 `ItemStack`，可修改传入副本后返回它。多个改写器按声明顺序执行。

- 输入：先应用数值修改器，再将每份所需数量交给改写器，返回数量最后乘并行数。恒等或只改数量时保留原物品／NBT 条件；实际改变物品或 NBT 时，按返回样板精确匹配消耗对象。
- 输出：改写器接收数量为 1 的样板；返回数量作为倍率，乘已应用数值修改器的产量。随机范围先按原范围掷点，再应用数值修改器和返回数量倍率，保留零产出与原概率分布。返回的物品和 NBT 用于空间检查与实际插入。
- 返回空堆表示主动将该需求数量设为 0；返回 `null`、抛出异常、或当前脚本缺少对应检查器／改写器都会拒绝结算。
- 检查、并行探测和实际结算会多次调用这些函数。检查器和改写器应只计算结果；计数、发奖和改世界状态应放在生命周期回调里。
- 结算使用共享事务。后续需求失败、容量不足或存储拒绝提交时，不保留前面需求的扣除与插入。

函数只存在于服务端。联机包、存档与配方副本保存稳定的回调标识；重载后由当前脚本重新绑定。同一配方请使用稳定的 `.id()`。删除必须的检查器／改写器后，旧在途配方会停住，恢复定义后可继续。

## 需求选项与时序

以下方法作用于**最近一条需求**：

| 方法 | 含义 |
|---|---|
| `.chance(0.5)` | 输入消耗或输出产生的概率 |
| `.nbt(object)` | 输入 NBT 条件／输出 NBT |
| `.previewNBT(object)` | JEI 的 NBT 显示覆盖，不改产物 |
| `.selectorTag('feed')` | 只使用结构中带该标签的端口；仍受输入组约束 |
| `.parallelizeUnaffected(true)` | 该需求不随并行数放大 |
| `.consumeDurability()` | 物品输入按耐久点支付；工具耗尽会损坏 |
| `.triggerTime(20)` | 改为在进度 20 触发一次；0 为正常阶段 |
| `.triggerRepeatable(true)` | 进度再次经过同一触发点时允许再触发 |
| `.ignoreOutputCheck()` | 不让该输出限制预先检查；实际插入仍须成功 |
| `.requirementTooltip('文字')` | 在 JEI 需求格增加说明 |

延迟触发适用于一次性需求；不能与能源或 `perTick` 需求叠加。0.118.1 起，触发时间按最终整数时长与原始时长的比例缩放，并限制在最后一 tick 以内；跳过进度时补结算，直接完成也不能绕过尚未执行的需求。重复触发指重新经过同一触发点，不表示定时循环。触发标记只在整次事务成功后写入，并随在途合成保存，避免重进世界重复支付。每次新开工会重置标记。例子与边界见 [修复记录](../归档/版本记录/修复记录-0.118.1.md)。

```js
ServerEvents.recipes(event => {
  event.recipes.modular_machinery_reborn.machine('kubejs:quality_press')
    .time(80)
    .itemInput('minecraft:iron_pickaxe', 5).consumeDurability()
    .fuelInput(2000)
    .itemInput('minecraft:redstone', 1).triggerTime(20)
    .itemOutput('minecraft:diamond', 1)
    .id('kubejs:durability_press')
})
```

`fuelInput()` 的单位是燃烧 tick，接受能提供燃烧时间的物品；消耗整件燃料，多余燃烧时间不保留。带容器余物的燃料须能放回容器，否则整次结算拒绝。无法损耗的物品不能支付耐久点。

其他入口：`.gasInput(id, amount)`、`.gasOutput(id, amount)`、`.gasPerTick(id, amount, io)`（需 Mekanism），`.ingredientArray([{item: 'minecraft:coal', amount: 1}, ...])`、`.smartInterface(type, value)`。流体／能源和催化剂原有 API 保留。适配器可写 `.adapter('minecraft:furnace')` 或另一台机器完整 id，再用 `.adapterModifiers([...])` 配置已有修改器格式。

## 生命周期事件

全局订阅使用 `MachineLifecycleEvents.<名称>(e => {...})`；机器或配方专属订阅使用其方法链的 `.on('名称', e => {...})`。升级也可以订阅相同名称。

| 名称 | 可读／可改写的内容 |
|---|---|
| `structureFormed`、`structureUpdated` | 控制器、世界、位置、机器 id |
| `machineTick` | 同上，以及 `phase`（START／END） |
| `recipeCheck` | 配方 id、阶段、并行数；`parallelism = n`、`setFailed(reason)`、`prevent()` |
| `recipeStart`、`recipeFinish` | 配方 id、进度、时长、并行数 |
| `recipeTick` | 同上与阶段；`prevent()` 阻止本阶段推进 |
| `recipeFailure` | 失败原因；`destructRecipe = true/false` |
| `factoryRecipeStart/Tick/Finish/Failure` | 对应配方事件，以及 `thread` |
| `resultChance` | 结算前；`setSeed(long)`／`random`／`setRandom(source)`，以及 `thread` |
| `smartInterfaceUpdate` | 接口 `type` 和写入后的 `value` |

`recipeCheck` 同样覆盖工厂开工，两阶段都在一次性输入支付前。`thread` 为 -1 表示普通控制器，普通工厂线程为非负数，核心线程为 -2 以下；用 `controller.getRecipeThread(e.thread)` 定位，不能把它当 GUI 行号。

分发顺序：全局事件、机器专属、配方专属、兼容升级。普通 `recipeStart` 在支付成功且控制器已武装后触发；`recipeFinish` 在产物已插入后触发。Tick START 阻止时不扣本 tick 资源，END 阻止时资源已支付而进度不增。全局事件的 `cancel()` 还会中断该 KubeJS 监听器链；专属回调推荐用 `prevent()`。

回调抛错时会记录错误；开工检查拒绝开工，可取消的 tick 会被取消。错误日志按回调标识在每次重载期间只记录一次。

## 控制器与工厂运行时

所有事件都有 `e.controller`。以下属性和方法针对当前控制器，修改只能在服务端线程执行：

| 接口 | 用途 |
|---|---|
| `customData` | 可读写持久 `CompoundTag`；可赋新 NBT 或直接 `putInt()` 等 |
| `statusMessage` | 自定义控制器状态文字；空字符串清除 |
| `progress`、`duration`、`parallelism`、`activeRecipe` | 当前合成；`progress` 可写，夹在 0 到时长之间 |
| `extraThreadCount` | 额外普通线程数，范围 0–32767 |
| `machine`、`pos`、`world`、`blockState`、`facing`、`ticksExisted` | 身份、位置、朝向、当前加载期间的 tick 数 |
| `ownerUUID`、`ownerPlayer`、`ownerName` | 所有者；离线玩家对象为 null，名字可能为空 |
| `get/setSmartInterfaceData(type, value)` | 读写智能接口数值；setter 按机器声明范围处理 |
| `getDynamicPattern(name)`、`dynamicPatterns` | 已匹配动态结构的长度与方向 |
| `getBlockPosInPattern()`、`getBlocksInPattern()`、`findBlocks(predicate)` | 已成型结构的位置／状态；不重新扫描或加载区块 |
| `rotateWithControllerFacing(offset)` | 将相对坐标转到控制器朝向 |
| `foundModifiers`、`foundMultiBlockModifiers` | 结构中当前生效的修改器 |
| `getMachineUpgrade(id)`、`hasMachineUpgrade(id)`、`machineUpgrades` | 兼容当前机器的升级与数量 |
| `recipeThreadList`、`getRecipeThread(ordinal)`、`getCoreThread(name)` | 工厂线程视图；找不到时为 null |
| `createCoreThread(name, ...recipeIds)` | 新增／覆盖运行时核心线程，下一次工厂同步时生效；保存到世界 |
| `removeCoreThread(name)` | 立即删除运行时核心线程声明；该线程正在加工时抛 `IllegalStateException`（不会排队"完成后删除"），不删除机器定义中的固定线程 |

**删除核心线程的实际契约**（P06-07）：`removeCoreThread(name)` 只接受**空闲**线程——该线程正在加工时抛
`IllegalStateException`，声明保留、已支付批次与库存不变，不会记录"完成后删除"的请求。删除运行时声明
也不影响机器定义中的同名固定声明（同名槽回退到固定声明）。

持续供料的线程不会自然排空：完工后引擎立即重开下一批，`FactoryRecipeFinish` 回调触发时该线程的
active 槽尚未清空（`isWorking()` 仍为 true），因此在完成事件里直接删除同样会被拒绝。安全做法是先确认
存在且空闲，只在空闲时调用：

```js
const thread = e.controller.getCoreThread('my_thread')
if (thread && !thread.isWorking()) {
  e.controller.removeCoreThread('my_thread') // 只在空闲时成功；busy 时抛异常
}
```

即使如此，这个示例也不保证持续供料的线程能排空——重开是即时的；要删除它需要先让线程真正空闲
（例如停止供料来源或另行否决重开），再执行删除。

运行时修改器使用具名覆盖，重复执行同一个名字不会累乘：

```js
MachineLifecycleEvents.machineTick(e => {
  if (String(e.phase) !== 'START' || !e.controller.formed) return
  if (e.controller.customData.getInt('heat') >= 100) {
    e.controller.addPermanentModifier('heated_speed', 'duration', 'input', 1, 0.5, false)
  } else {
    e.controller.removeModifier('heated_speed')
  }
})
```

`addModifier(name, target, io, operation, value, affectChance)` 添加临时修改器，`addPermanentModifier(...)` 添加持久修改器；`removeModifier(name)` 删除同名项，`hasModifier(name)` 查询。运算 0 为加算，1 为乘算；目标为 item／fluid／gas／energy／duration 等已有类型。修改器作用于各需求自己的数值／概率桶。

运行中会移除开工快照中的旧脚本贡献，再合入当前脚本修改器，保留结构及已支付催化剂的冻结贡献。修改在下一次结算计算时生效；在 RecipeTick 回调中写入时，当前 tick 已取出的快照留到该 tick 结束。时长变化不会绕过实际产物插入检查。

线程视图提供 `progress/duration/parallelism/recipe/isWorking`、`customData/statusMessage`、同样的具名修改器，以及 `setRecipes(list)`。线程临时修改器在该批合成结束／销毁时清除；普通控制器的临时修改器在该批结束时清除。工厂控制器级的临时修改器供多个线程共享，需显式移除；不会在其中一个线程结束时清掉其他线程的效果。持久修改器须显式删除。

## 升级定义与升级回调

```js
MachineRegistryEvents.registry(event => {
  event.upgrade('kubejs:counter_upgrade')
    .localizedName('计数升级')
    .item('minecraft:paper')
    .field('max-stack', 1)
    .field('compatible-machines', ['kubejs:quality_press'])
    .on('recipeFinish', (e, upgrade) => {
      const data = upgrade.customData
      data.putInt('completed', data.getInt('completed') + 1)
      upgrade.setCustomData(data)
    })
    .register()
})
```

升级声明复用原有 JSON 校验，脚本定义优先于同名数据包／配置定义。`.item(id)` 可重复，生成载体映射。`field()` 支持已有的 `dynamic`、`level`、`stackable`、`modifiers`、`descriptions`、兼容白名单／黑名单等字段。

升级回调只对结构中实际存在且兼容的升级执行；第二个参数提供 `id`、`count`、载体数据副本 `itemData`、总线级持久 `customData`，修改总线数据后调用 `setCustomData()`。每个升级总线分别持有数据。脚本移除后，专属回调及脚本声明随下一次重载清理。

## 验证范围

这些接口已接入实际结构与结算代码。离线测试会直接执行生产 Java 逻辑及真实 Rhino 函数转换；游戏内联机、真实存档升级和整合包脚本仍需实机验收。旧版 CraftTweaker 脚本文件不能直接运行，需要改写为以上 KubeJS 入口。第三方配方适配器和额外能源／魔法后端的既有待移植范围不会因为添加脚本入口而自动实现。

### 升级定义重载（0.121.16）

重载只使用当前数据包、配置目录及当前脚本中的升级定义和物品映射。删除定义后，对它的残留映射会报未知升级并跳过；无效的新定义不会沿用上次加载的旧版本。不同来源仍可分别声明类型与物品映射，但类型必须在本次加载的有效来源中存在。

### 工厂槽位配方限制（0.121.17）

一个空闲槽因配方列表或槽位修改器接不了当前配方时，会尝试其他空闲槽；仍有线程额度时可尝试新槽。不会绕过任何槽的配方限制或线程上限。新槽预检失败且没有脚本配置时不保留空壳槽；检查回调已经写入的配方限制和自定义状态会保留。

### 运行失败事件原因（0.121.19）

普通与工厂运行失败事件的 `cause` 根据当前 tick 的需求、已到期延迟输入、分组和选择标签诊断，不再重新要求已经支付的开工物品。诊断只预留虚拟资源，不重复支付；若再次检查仍可付而实际结算被拒绝，使用通用 tick 结算失败键。它不能确认任意外部处理器的内部拒绝细节，也不等同于界面的开工失败字段。
