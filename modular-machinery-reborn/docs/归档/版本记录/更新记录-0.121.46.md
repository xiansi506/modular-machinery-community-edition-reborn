## 问题

- **P02-01**：屏幕左键读取 `menu.getCarried()`，但 `MeFluidConfigPacket.sendItem` 只发 id/count；服务端 `new ItemStack(id)` 重建物品，自定义名、附魔、药水等 NBT 全部丢失。`MeItemBusLogic` 用 `ItemStack.isSameItemSameTags` 维持目标量、`AEItemKey` 也按标签认身份，于是会去请求错误的变体；空光标或伪造 id 也会照写。
- **P10-21**：`EnergyDisplay.display` 把 `long` 乘 `double`：FE/RF 的 `2^53+1` 丢低位，`10^18-1` 先舍入到 `10^18` 而跨到 E 缩写；`DisplayNumbers.grouped` 只收 `double`，能量仓物品的完整数字同样丢位。

## 修复（生产白名单内 3 份源码）

- `network/MeFluidConfigPacket.java`：ITEM 分支改走私有 `cursorCopyFor(menu, id, amount)`——用 `ForgeRegistries.ITEMS.getKey(carried.getItem())` 核对服务端 `menu.getCarried()` 与请求 id 一致，再用 `copyWithCount(夹到 maxStackSize)` 深拷贝；不匹配返回 `null`（拒绝写入、保留旧配置）。没有新增 wire 字段，`sendItem` 的 single/数量契约不变。类注释写清「身份来自服务端光标栈」的原因与边界。
- `config/EnergyDisplay.java`：新增整数除数（FE/RF = 1、EU = 4）。`display(long)` 在除数为 1 时原样返回，否则 `Math.floorDiv`（负数也向负无穷取整）。`multiplier()` 契约与四个单位的比例不变。
- `config/DisplayNumbers.java`：新增 `grouped(long)`（`DecimalFormat.format(Long)`，逐位精确、沿用同一 `#,###` 与本地化分组符）；`grouped(double)` 保留给既有消费者并注明其在 2^53 以上不精确。
- `block/MachineHatchBlock.java` 未改源码文本：它的 `grouped(long)` 调用在重新编译后自动命中新重载（字节码 `invokestatic grouped:(J)`，已核对）。
