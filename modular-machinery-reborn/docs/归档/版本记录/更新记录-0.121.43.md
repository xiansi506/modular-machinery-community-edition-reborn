# 更新记录 0.121.43（2026-11-03）

## 问题

- **J1 / P07-03**：`evaluateModifiers` 只旋转修改器 offset，`accepted` 仍按北向原文匹配。定义为北向的“炉子朝东→能源×0.5”在西/南/东控制器上消失，反而未旋转的东向炉子被错误接受（实际 5/10 FE 结算对照见结果报告）。
- **J2 / P07-04**：`DynamicPattern.match` 用已旋转的 `partRotations/endPartRotations` 量长度，`expand` 却只旋转坐标、写回未旋转 matcher。四向都量出 2 节，只有北向能通过展开后的有效结构复查与 `MachineRegistry`；`runtimeStructure` 先 `expand(2,0)` 再整体旋转，四向都接受，形成内部矛盾。

## 修复

- `MachineModifier` 新增 `acceptedAt(rotationSteps)` / `matches(state, rotationSteps)`：对每个候选调用既有 `BlockMatcher.rotateYCounterClockwise()`，展开返回列表的全部候选并按描述符去重；`MachineControllerBlockEntity.evaluateModifiers` 改为调用该入口。保留部分属性通配、耦合属性精确候选、来源描述符不变、每个修改器只激活一次。
- `DynamicPattern.expand` 按 `floorMod(steps,4)` 复用构造时缓存的已旋转段；`addSection` 只做“已旋转段内坐标 + 段起点”，不再二次旋转坐标或状态。量长度、展开、`runtimeStructure` 共用同一份约束。
- 未改 `BlockMatcher`/`MachinePattern`/`MachineRegistry`/网络/协议/3D renderer；未扩 P07-02、P07-05、P07-06。
