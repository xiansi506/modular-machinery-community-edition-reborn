## F3 / P07-01：script-checker 校验错误补部件定位

0.121.36 的类型校验（只接受非空白字符串 token）验收确认有效，但错误 where 只有机器名——同机多个部件时无法定位是哪一个写了非法规则。本版：

- `MachineSchema.readParts` 循环带部件序号，`validateScriptChecker` 的 where 追加 `part N (x=…, y=…, z=…)`：坐标范围单值直接给数字、多值给 `[min..max]`（新增 `partWhere`/`span` 辅助）。
- parts-end 读取处 where 加 `'parts-end'` 段标记（此前 parts 与 parts-end 的 where 相同，无法区分段）。
- 四条读取路径（根 parts、坐标数组展开、dynamic 段、multi-block-modifiers）全部生效——都经 `readParts` 一处校验。
- 类型校验、正文原样保留（不 trim/不改大小写/不要求 ResourceLocation/不要求加载时已注册）、客户端跳过服务端 checker 的契约均不变。`MachinePattern` 本版未改。

夹具按验收报告纠正 tick 装置：先注册真实机器表、合法 checker 回调计数证明真实结构检查触发（calls=1）、再注入非法规则并重建旋转表、另一个控制器安全拒绝成型（不抛、不 formed），无无条件 PASS。补齐交接组合：单元素数组、parts-end、多块修改器、四朝向（每朝向真实触发一次）、未注册 token 运行期实际拒绝、token 字符串身份原样（`Audit:Case Probe` 含大写与空格，注册同名才命中）。

## G3 / P10-17：层枚举统一到实际层索引

0.121.37 已把回退检查切到 `structuredLayers` 实际层索引，但 `updateLayers` 残留旧版 `for (y = min..max)` 逐整数枚举（空层靠「无条目即完整」跳过，语义等价但复杂度随高度跨度增长）。验收装置实测：Y=0 与 Y=10000 两层实块的结构，`startFromRaw` 发生 10003 次全位置表扫描。本版 `updateLayers` 收敛到 `lowestIncompleteLayer`（同一实现、同一索引），扫描次数只随实际层数增长——同结构实测 **4 次**。start/clear/换结构/回退/前进全部入口经此收敛；不加载区块、不建世界全局监听的边界不变，匹配语义不变。

夹具补齐：负 y 层排序与投影（Y=-2/Y=0）、start→clear→start 与 start→start 换结构索引重建、两种拆底层回退、START 相位、整机清除、维度/距离32/logout 清除；复杂度用透明 entrySet 计数证明（不是要求特定方法名或精确次数）。
