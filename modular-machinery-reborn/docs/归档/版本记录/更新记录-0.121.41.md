## H1 / P01-01：结构校验提前到 root 发布前，原文逐字保留

- 0.121.40 的问题是校验时机：原文页 `collect()` 先把原文解析进 `root`，切页 `init()` 才发现结构不符并回落——此时旧模型已被非法对象替换，原文框又由 `editable(root)` 格式化重建，验收的两条新增断言（原文逐字、旧模型保持）失败。
- 现在 `collect()` 原文页分支先在局部变量解析并调用 `RecipeDocument.formStructureError`；通过才发布 `root`，失败只设带 `requirements[序号].字段` 位置的消息并留在原文页。`init()` 的同一检查保留为进入表单模型前的最后防线。
- 新增 `sourceDraft` 逐字草稿：原文页编辑实时写入、重建前从原文框收集、原文页从草稿还原；表单提交后清空。缩窗走既有 `savedValues` 并在应用后同步草稿。
- 校验范围不变（requirements 数组/条目对象/type 非空字符串/已知类型布尔），不要求完整服务端语义，不删除未知高级需求字段。

## I2 / P10-08：重建与未确认意图使用一致策略

- 0.121.40 的问题是重建时机：`init()` 无条件 `groupInput = menu.groupInput()`，但保留 `localIntent=true`，确认到达后 `containerTick` 永远等不到 `menu==mirror`，按钮停在旧状态且意图不清除。
- 现在 `init()` 在 `localIntent` 为 true 时保留本地镜像（仍待确认的同一意图），无意图时才采用菜单快照；确认到达后由既有 `containerTick` 清除意图。菜单 wire/服务端处理/数字提交/关闭不提交数字的语义未改。
- 旧协议“拒绝与延迟不可区分”的限制如实保留，不新增协议。
