## 三、这个项目的规矩（违反了会被指出）

1. **不许无据推断**：每个判断要有代码位置或实测证据。查不到就写「未查到」，不要猜。
2. **「看起来合理」不是依据**：原版可观测之处绝不自造默认值或行为。
3. **过宽的断言等于没断言**；**假失败与真失败一样有害**；边界要由数据算出来。
4. **「日志里没有报错」不提供信息**：静默失效只能用运行时探针或实机 settle。
5. **看不见的状态必须能被问出来**：`/mm-diagnose` 就是为这件事存在的。
6. **诚实报告未验证的部分**：说「已交付」必须同时说「哪些没实机验证」。
7. **中文技术文档**；术语准确，不造译名。

### 与所有者配合

- 实机反馈要具体到「做什么 → 该看到什么 → 不对说明哪里坏了」，不要让所有者数坐标或猜。
- 每步汇报「改了什么、依据、哪些没验」；改动用中文约定式提交，网络允许时推送。
- 所有者会自己试并回报现象；「第 1 条没变色」这类反馈比自测更有价值，先按现象查，不要先改代码。

9. **写临时 `.ps1` 时**：先 `Set-ExecutionPolicy -Scope Process Bypass -Force`；文件必须纯 ASCII（PowerShell 5.1 按 ANSI 读，中文会变乱码）。本机没有独立的 `pwsh` 命令，只有 `powershell.exe`，但 DSH 的 `pwsh` 工具可正常用。

## 十、这个项目反复吃过的亏（带走）

1. **`PASS` 只证明断言问过的那件事**，不证明日志里没有警告。红绿结果要连同证据文件一起看。
2. **涉及 API 形状的判断必须查签名**。凭记忆写过「1.20.1 的 `BlockColor` 拿不到位置」，`javap` 一看记反了。
3. **`text.contains(X)` 对「在别处加一句合法代码」是失明的**。同一条断言被骗过两次；第三版按方法体判断才咬住。
4. **文档里的「部分完成」要对着代码核**。`craftcheck.failure.*` 曾写「部分已补」，对表才发现 9 种键缺 2 种。
5. **文档也可能把缺口本身写错**。波 6 的「光照均匀」前提经核实不成立，整项被移除。
6. **探针自己说错话比没有探针更糟**。「Jade 流程模拟」原来只测第一个仓，误导过一次。0.94.0 又一例：node 替换脚本未命中仍打印 ok，菜单重构静默失败、真实槽残留到实机才炸——**脚本化替换必须校验命中再报成功**。
   6a. **给方块引入/更换透明 overlay 模型时，固定三步**：量透明像素（PowerShell 数 A=0）→ 过 `ClientSetup` 渲染层名单（cutout）→ 名单变更进迁移日志。总线（0.86.1）与供应器（0.96.5）先后踩同一坑，规则由此成文。
7. **反复失败的机制，先做可观测性再改它**。Jade 替换器失败三次、表现完全一样，加计数器后才第一次区分「没被调用」与「调用了没定位到」。
8. **红必须真的是红**。生产代码已改后再补红跑，是假红；要么用旧提交/暂存恢复到改动前，要么明确写「这轮没有红证据」。
9. **文档状态会落后于代码**。开新会话的第一件事永远是核对 `git`、版本号、已部署 jar 哈希，而不是相信上一份交接里的数字。

## 十一、项目背景、代码地图与完成口径

### 11.1 定位与边界

这是把 1.12.2 的 Modular Machinery: Community Edition（MMCE，2.3.2）移植到
Minecraft 1.20.1 / Forge 47.2.0 / Java 17 的续作。目标是保留模块化机器、仓口、
多方块结构、配方、JEI 与 KubeJS 扩展，不把旧版内容做成内置机器。

- jar 不内置机器与配方（Q3），内容通过数据包、文档与示例分发；`example-datapack/` 只是参考。
- 许可证 GPL-3.0，见根目录 `LICENSE`。
- 仓库：https://github.com/xiansi506/modular-machinery-community-edition-reborn
- 旧源码只作参考：`C:\Users\kk07H\Desktop\模组\_mmce-src\ModularMachinery-Community-Edition-master`。
  可以看资源、玩法与旧行为，不复制 1.12.2 / Cleanroom 的 Java 类。

### 11.3 配方 JSON 的硬约束

- 根级 `type` 固定是 `modular_machinery_reborn:machine`；`requirements[].type` 才是需求种类。
- 需求 `type` 接受带命名空间和不带命名空间两种写法；未知类型应加载报错，不静默跳过。
- 改一个字段要同时过：`MachineRecipe`、`ModRecipeSerializers`（JSON 与网络读写）、KubeJS schema、JEI 展示、示例、网络包。

### 11.4 “做完了”的四步口径

1. **旧版有没有真实消费者**——不是死代码，也不只有 CraftTweaker 能碰到。
2. **本版有没有实现**——读代码和签名，不靠文档。
3. **离线复现器有没有真驱动**——红先绿后，证据由复现器自己写。
4. **实机有没有人打开/操作**——没有就写“已构建、未实机验证”。

源码里有链路不等于实机通过；文档写“完成”也要对回代码。`color` 是反例：
0.62.0–0.62.8 源码链路齐全，实机到 0.62.9 才修好“成型后白、拆块后才显色”。
`prefix` 与 `controller-bounding-box`（0.80/0.81）目前只有离线与形状查询证据，未进游戏。

## 十二、交付与发布自检

### 12.1 SRG 污染检查

出货后，在 `modular-machinery-reborn` 目录下对 `build\reobfJar\output.jar`（以及部署到 mods 的同一个 jar）跑：

```powershell
javap -classpath build\reobfJar\output.jar -c -p com.reborn.modularmachinery.block.ModBlocks |
  Select-String 'CREATIVE_MODE_TAB|f_\d+_'
```

期望：`CREATIVE_MODE_TAB` 0 行，`f_<digits>_` 至少 1 行。构建件和部署件都要查。
**0.99.0 已检查**：用 ASCII junction `C:\mmwork\modular-machinery-reborn` 执行 `javap -classpath build/reobfJar/output.jar -c -p com.reborn.modularmachinery.block.ModBlocks`，结果 `CREATIVE_MODE_TAB_COUNT=0`、`SRG_FIELD_COUNT=1`；构建件与部署件 SHA-256 同为 `02D9975659B388D354AA51D277E64456AC9986834E43A135266D7535F132D490`。0.82.0–0.97.4 的结果按各版迁移日志记录，不外推。

### 12.2 顺序不能反过来

若所有者明确要求运行离线复现器，固定顺序：**复现器 → 出货 `build`（不加 `clean`）→ SRG → 部署**。未明确要求时，不新增或运行测试/复现器；可按任务需要执行 `compileJava`、`reobfJar` 与 SRG 检查，并如实报告证据边界。0.85.0–0.99.0 都是 compile/reobf/SRG/部署通过、未运行复现器或进游戏。

`m6cVerify` 依赖 `jar`，会重写 `build/libs/`，但它不会替你重做 `reobfJar`。
先 `build` 再跑复现器，`build/libs/` 会回到未 reobf 状态，`reobfJar/output.jar`
也可能不再对应最后一次源码。要出货就按上面的顺序重来。

### 12.3 配置注册

同一模组每种 `ModConfig.Type` 只能 `registerConfig` 一次，`ForgeConfigSpec.Builder`
只实例化一次。改配置前先 grep `.registerConfig(`；`push/pop` 是路径累加，
验收时把 spec 渲染出来对真实文件，别只信文档里的路径。

### 12.4 复现器自己会腐坏

断言类引用已删的类、重载写错，都会让 `m6cVerify` 编译失败。跑不起来时先修复现器，
不能拿上一次 class 的绿灯当本次结论。新断言类底部要同时转发
`check(String,long,long)` 与 `check(String,String,String)`，只写一个重载会解析失败。

### 12.5 证据

证据必须由复现器自己写进 `_audit/m6c-verify/harness-run-<version><suffix>.txt`，
文件里要有 `SUMMARY: ...`。报告里的计数从本次文件读，不引用旧数字。
红证据与最终绿证据都保留；中间假失败证据可以删，但要在迁移日志里说明原因。

### 12.6 可见界面与每帧路径

新增可见界面或每帧路径，交付时必须附最小实机清单：打开哪个界面、点哪里、
应该看到什么。所有者确认前只标“已构建、未实机验证”。
哨兵值（-1、null、`indexOf` 未找到）不得未经边界检查进入列表下标。

### 12.7 构建不是字节可复现的

历史记录里同一份源码三次 clean build 得到过不同哈希。SHA-256 只证明
“构建件、部署件、归档件是同一个文件”，不证明能从源码重建出同一字节。

### 12.8 版本与归档

修复递增 patch，新增功能递增 minor；同时改 `gradle.properties` 和 `迁移日志.md`。
发布归档不覆盖旧版本；部署新 jar 时删掉同名的旧版本，避免 mods 目录里同时存在两份。
