## 3. D1 / P02-04：投影空候选隔离

**白名单：** `network/ProjectorResponsePacket.java` 的处理回调。报告：[P02-a](../代码勘测报告/P02-a-网络消息.md)。

目标和验收：

- 一个位置混合合法/非法候选时保留合法候选；该位置全部无效或原本列表为空时，跳过该位置，不能调用add(empty)。后面的合法位置仍可处理。
- 全部位置无效/消息为空时安全返回，不启动一个虚假的有效新投影；保留现有空回应不启动投影的语义，不借机更改旧投影生命周期。
- 正常结构、attached坐标、实际候选顺序/数量不变；使用实际消息处理器与实际builder，不只测一个自写过滤函数。
- 如涉及Dist.CLIENT回调的夹具替身，明确只验证线程回调/构建，不写成真实Forge联网或GPU验收。

这是异常服务器回应/版本不一致时的客户端健壮性，不应宣传为修复普通玩家远程攻击。部分显示投影不代表结构有效性检查通过，不改协议或服务端结构定义。

## 4. D2 / P04-04：错误字段大小写不能静默失效

**白名单：** `recipe/IngredientArrayParser.java` 的共同字段检查；必要时限 `recipe/CatalystParser.java` 的对应入口。报告：[P04-b](../代码勘测报告/P04-b-物品NBT与备选原料.md)。

rejectUnknownKeys对字段名转小写后检查，真正读取却按原名查找，Amount/Chance/NBT之类会被接受但不生效。目标采用**现有读取器的规范字段拼写**严格检查，错误大小写明确报错；不另造大小写无关的新格式。

至少验证真实入口：

```json
{"type":"ingredient_array_input","io-type":"input","items":[{"item":"minecraft:stone","Amount":8}],"Chance":0,"NBT":{"locked":"yes"}}
```

- ingredient_array_input外层、items条目、catalyst都覆盖Amount/Chance/NBT/Nbt-display等错误拼写，错误含来源与原字段名。
- 正确amount/chance/nbt/nbt-display、公共selector/trigger等选项按其真实规范拼写继续接受；先检查allowed集合是否已有合法驼峰键，不能一律把规范字段改成小写。
- 成功解析后核对实际数量、概率和NBT匹配，不能只检查“未抛异常”。未知字段仍按原策略拒绝。
- **只校验需求结构字段，不递归规范化NBT数据键、物品ID值、标签值、脚本字符串。** NBT中的自定义`Amount`等键必须保留，不能全树转小写。

不改P04-05列表匹配算法、通用配方序列化或其他数值精度问题。

## 5. D3 / P06-10：额外线程数int存读档

**白名单：** `block/MachineControllerBlockEntity.java` 的extraThreadCount持久化；仅必要注释同步可涉及公开字段说明。报告：[P06-c1](../代码勘测报告/P06-c1-并行额度线程上限与时长补偿.md)。

Java setter接受40000，当前写short后读成-25536。目标按int保存，并兼容已有short数值的旧档，恢复时保持非负规则。原NBT键名保持不变，不把高位直接丢弃或把Java API强行缩回32767。

验收：

- 0、1、32767、32768、40000、Integer.MAX_VALUE通过实际BE存读档往返；负值按setter/恢复规则处理。无需分配对应数量的真实线程。

- 机器基础max-threads=0时，Java设置40000并存读档后仍有正额度，真实普通批次可开工；只跑少量槽位。
- KubeJS `setExtraThreadCount` 的0～32767现有限制保持，不拓宽脚本API，不改网络字段、不承诺P02-02菜单short同步已修。
