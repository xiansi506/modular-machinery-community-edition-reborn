# P03-d：失败重载与缓存失效

日期：2026-10-29。基线 0.121.0，Git HEAD `f94ba299e37f0975ac5255f90671f990bacfc61a`。本轮只做离线勘测，不改业务代码，不运行游戏。

## P03-14：后置监听器失败后，全局机器表不会回滚（P2）

**触发与影响：** `/reload` 中，机器加载器已经执行并替换全局机器表，随后其他重载监听器失败。原版只在整次资源加载成功后替换服务器资源、调用 `PlayerList.reloadResources` 并触发客户端同步；本模组的静态机器表却已经改成新定义，失败路径未见恢复旧表的逻辑。因此会形成“旧服务器资源/配方与旧客户端定义，搭配新全局机器表”的不一致。具体在途合成影响归 P06 验证，本轮未证实物品复制或丢失。

**离线证据：** 运行实际 `MachineLoader` 和实际 `SimpleReloadInstance`，在机器加载器后添加一个测试专用的失败监听器。开始时服务器和客户端表均有 `audit:old`，隔离目录提供 `audit:new`；整体 future 以预设异常失败后，实际服务器表只有 new，客户端表仍只有 old。没有在失败后人为调用客户端更新。本测试包含完整机器加载器执行，额外补齐了本地 javafmllanguage 依赖，未复用 P03-a 中尾部类加载失败作为此次失败来源。

**调用链核对：** 当前本地 1.20.1 Forge 源码中，`ReloadableServerResources.loadResources` 将模组监听器附加到原版监听器之后，待整体 future 完成才返回新资源；`MinecraftServer.reloadResources` 在成功的 `thenAcceptAsync` 中替换资源；`PlayerList.reloadResources` 才发布 `OnDatapackSyncEvent`。项目 `MachineLoader.apply` 在自己的加载阶段调用 `MachineRegistry.replace`，`MachineDefinitionSync` 只响应上述同步事件。这使故障注入的场景对应真实重载阶段关系。

**边界：** 故障监听器是人为注入，未复现某个具体第三方模组的自然异常；客户端表留旧是没有执行成功同步的实际状态，测试未运行 MinecraftServer 或发送真实网络包。不能说正常成功的 reload 也必然发生这个问题，也不能声称已经在真实整合包观察到它。配置/重载由有权限作者操作，不属于普通玩家远程越权。

**位置：** `machine/MachineLoader.java:174-196`、`machine/MachineRegistry.java:95-123`、`network/MachineDefinitionSync.java:39-50`；本地依赖对照 `MinecraftServer.reloadResources`、`ReloadableServerResources.loadResources`、`PlayerList.reloadResources`。

**建议：** 将待发布定义、旋转表、源 JSON 等组织为同一加载周期的快照；所有依赖监听器应明确读取候选快照还是已发布快照，成功时统一发布、失败时保留或恢复旧周期。适配器生成当前依赖新机器表，因此不能只把 `replace` 随意延后到同步事件。回归应包含前置/后置失败、成功重试、玩家登录与失败后继续加工；不以成功后补发新表来掩盖服务器资源仍为旧版的问题。

## 正常路径和缓存检查

- 用实际加载器及重载协调器验证成功重试、机器 ID 改名和最后一份定义移除；在成功后显式调用实际客户端接收函数，旧机器 ID 在两端都被清除。实际游戏中的同步事件未运行。
- 用实际 RecipeManager.replaceRecipes 与 MachineRecipeIndex 验证：表未变时重用索引；同 ID/同规模替换取得新配方对象；配方改归属机器后旧分组清空；删除后清空；两个 RecipeManager 的内容不互相污染。离线手动绑定了机器配方类型，未验证 KubeJS 或其他模组直接原地修改 recipe map 的情况。
- 本轮没有发现上述正常替换路径的缓存残留，不将此前 0.118.4 已修复的索引问题重复报告。缓存依据配方表身份失效；在途加工执行副本的设计和资源结算留给 P06。
- `MachineEvents.post` 在重载事件开始时直接清空 ScriptHooks、升级脚本暂存和 MachineDefinitions。真实 KubeJS 周期若在后续阶段失败，这些状态是否需要与旧服务器资源一起恢复，尚未通过完整脚本重载证明；作为与 P03-14 相关的生命周期线索移交 P11，不另计已确认问题。缺失回调的 fail-closed 行为本身不自动算作漏洞。
