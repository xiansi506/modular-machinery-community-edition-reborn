## P11-01（P2）：全局配方检查脚本异常后仍允许开工

实际脚本：`MachineLifecycleEvents.recipeCheck(e => { throw new Error('intentional global failure'); });`。原生Forge总线→实际LifecycleEventsJS→原生KubeJS/Rhino执行了一次该监听器，记录脚本错误后返回；真实RecipeCheckEvent的failureReason仍null，取消位仍false。桥丢弃EventHandler.post结果，且未像客户端桥一样安装错误跟踪。调用者据该事件检查开工，若作者将许可/环境限制写在异常点之后，检查会被跳过。这不是普通玩家获得脚本权限，也未证明资源复制。

对照：同一真实Rhino错误发生于MachineBuilder.on('recipeCheck',...)绑定回调，经ScriptHooks处理会setFailed，且后续回调仍执行。全局正常调用cancel也能阻止普通tick。因此不能把ScriptHooks的异常保护推广到全局事件桥。

建议：为服务端全局桥增加类似ClientEventsJS.post的独立错误跟踪，按事件种类失败/暂停/取消；补全普通及工厂START/END资源结算组合。当前仅复现检查载荷状态，未运行真实机器、扣料或断言全部全局事件都同样失效。问题未修。
