## P04-15：可空修饰符目标的时长契约未实现（P3）

**证据与位置：** 公开 `RecipeModifier.multiply(null,0.5f)` 可以正常构造。实际 RecipeModifiers.applyDuration(100) 返回 100；以显式 Target.DURATION 作同样修饰返回 50。null 目标经 RecipeModifier.write/read 和 RecipeModifiers.save/load 都保留，保存后 applyDuration 仍返回 100。

RecipeModifier 的 nullable target 和相关注释将 null 描述为时长伪目标，RecipeModifiers.apply(null,...) 也路由到 applyDuration；但 `RecipeModifiers.java:114-140` 仅筛选显式 DURATION，直接跳过 null。问题在应用契约，不是网络把目标丢掉。

**旧版对照：** 本地 1.12.2 `common/crafting/helper/RecipeCraftingContext.addModifier:645-663` 明确将 null target 归入 REQUIREMENT_DURATION，支持注释所描述的含义。

**影响边界与建议：** 当前普通 JSON 要求目标字符串，仓库主源码未找到直接构造 null 目标的生产调用；主要影响 Java API 使用者、保存含 null 目标的规则，不能说普通 duration JSON 已失效。统一规范化为 DURATION 或在应用时明确处理 null，覆盖直接构造、合并、网络和存档。若决定不支持 null，则应调整 API、读取与文档并明确迁移，而不是继续静默忽略。

## P04-16：程序化数字接口需求的失败文案在复制时丢失（P3）

**原生复现：** `new InterfaceNumberInputRequirement("mode",10,20,"audit:custom")` 在当前值 0 时 startFailure 返回 audit:custom；通过实际 MachineRequirementParser.copy 后，范围仍是 10～20，匹配仍失败，但返回默认失败键。

**原因与位置：** `RequirementTypes.java:424-438` 的写入仅有接口名、min/max，读取固定传入 null；`InterfaceNumberInputRequirement` 的 notEqual 定义字段未进入复制使用的网络表示。它是诊断文本丢失，不是范围条件丢失。

**边界与建议：** 当前 JSON 解析器本来就传 null，自定义类型级文案从机器定义读取，因此常规 JSON 的机器类型文案不因本复现而失效。当前仓库中其他生产构造调用也未传入非空覆盖值；这项限定为公开程序化重载的复制契约问题。服务端完整复制应保留覆盖字段；若同时改协议需成对修改和评估版本。回归包含覆盖文案、空/空白回退、机器类型文案，以及实际 Java 附属模组调用。

## P03-10 扩展：数字接口条件接受非有限 float

`InterfaceNumberInputParser.requireNumber:92-103` 确认 JSON number 后直接 getAsFloat，没有 Float.isFinite 检查；构造器也没有检查有限性。

- `minValue:-1e1000,maxValue:1e1000` 解析为负/正 Infinity，实际 canSatisfy 同时接受 Float.MAX_VALUE 和 -Float.MAX_VALUE；真实复制后仍保留无穷范围。
- `value:1e1000` 也加载为 Infinity，实际对有限值 0 匹配失败。没有用手工构造的 NaN 充当合法标准 JSON。
- 原 P03-10 已登记机器侧智能接口默认值的非有限问题，此处补充独立的配方条件读取入口，不另编号。应同时检查定义默认值和需求条件，不能只修存储 setter。

建议读取范围/等值时拒绝非有限值，给出配方 ID 和字段；网络/程序化构造如需容错应明确策略。接口本来就是 float 数据，不将正常 float 精度、合法小数或约定的包容端点直接算作漏洞。

## 正常结果与旧版语义

- 实际 range 10～20 包含 10/15/20，拒绝 9/21；缺失接口报告 missing，与有效数值 0 区分；范围不符报告默认 mismatch，匹配成功返回无错误。
- value 单值和只写 minValue 的精确匹配正常；只写 maxValue、倒置范围、字符串/null 数值、空白接口名和输出方向被拒绝。
- 并行 128 及 wildcard ×0.5 不改变数字接口范围；apply 不扣资源。实际 MachineRecipe.canStart/start 通过合法值，拒绝不符值，执行副本继续使用相同条件。
- 旧需求命名空间、接口名、正常 min/max、selector-tag 和固定并行标志在实际需求复制后保留。
- 本地 1.12.2 RequirementInterfaceNumInput 的范围是包含两端的 float 比较，区分 missing/mismatch，从类型读取文案，deepCopyModified 不修改范围；本版这几条正常路径与之相符。旧 JSON reader 返回 null，当前 interface 字段避免与需求 type 冲突，是已经记录的新增表达方式。

没有新的性能实测结论，也没有验证真实控制器编辑、重载和多线程状态；这些留 P06/P10/P11。接口长期运行过程中值发生变化的时序也不由一次 start 测试证明。
