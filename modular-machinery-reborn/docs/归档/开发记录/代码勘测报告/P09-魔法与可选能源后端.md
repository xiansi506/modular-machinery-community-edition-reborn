## 对 P05-c3 移交问题的静态回答

1. **环境身份准确性**：Will 与 Aura 的 `Access.identity()` 都是 `(Level, ChunkPos.toLong())`（ChunkKey），同一区块内多仓共享同一身份——P05-c3 的共享事务语义适用；MANA/LP/EMBER 身份是 hatch 本体，AIR 身份是 PNC 的 air handler 实例。
2. **Will 默认逆向恢复是否完整**（P05-c3 标注"留 P09"）：Blood Magic 3 的区块 Will 是"每类型每区块单一池"（`WorldDemonWillHandler.getCurrentWill(Level,BlockPos,type)` 按区块聚合），不存在 Aura 那种抽吸点分布；`Access.move` 的 fill/drain 直接改这个池，因此默认逆向恢复（amount 快照 + 反向 move）在池粒度上**完整**。静态结论，未运行真实 API。
3. **Aura 空间分布**：`AuraBackend` 的快照是**整个区块 INBTSerializable NBT 副本**（含 drain-spot 分布），restore 后 `markDirty`——回滚保分布，代价是每次事务校验都做一次全区块序列化（见优化候选）。
4. **Ember 收发与空气均压**：Ember 是仓内 double 缓存 + 代理实现 `IEmberCapability`（`setEmberCapacity` 有意忽略——容量归仓配置，外部 NBT 不可改容量；客户端容量从同步 NBT 读且有 0..1e9 上界）。空气完全委托 PNC 真实 handler（`tick(BlockEntity)` 让 PNC 自己做均压/过压/泄漏），本模组的 `Access.move` 只 `addAir` 并返回**实际移动量**（air()-before），`maximum()=volume*dangerPressure`、`minimum()=-volume`（真空），符合 P05-c3 的有符号移动契约。

## 通过的静态契约

- **可选依赖类加载安全**：魔法方块族按 `ModList.isLoaded(family.modId)` 注册（MagicBlocks.register），后端 ctor 的 `type()` 反射抛出只在"注册时在、运行时不在"的不可达组合下发生；模组被移除后旧存档走 vanilla"未知方块实体类型"跳过，不崩。全部反射只触公开 API（ApiReflection 有方法缓存）；PNC handler 经官方 factory 创建， dispersion/vacuum/overpressure 归 PNC 所有。
- **LP 结算守卫**：BloodMagic LP 每 5 tick 从 SoulNetwork 补充仓内缓存（输入）或把缓存归还网络（输出）；`moved<0 || moved>容量上限` 时用 `setCurrentEssence(before)` 补偿并放弃，`moved > Integer.MAX_VALUE-stored` 溢出守卫在位。事务路径只动仓内缓存（network 补给是后端自己的旁路），恢复完整。
- **数值与单位**：MANA 全程 int 且夹在 [0, manaCapacity]（load 时负值归零、超量截断——与流体侧 P07-13 不同，此处无负灌入形状）；WILL/EMBER 是 double 且 `Double.isFinite` 处处把关；AIR 用 mL、压力门用 volume×dangerPressure；`MagicConfig` 在 SPEC 未加载时给默认值（离线安全）。
- **OptionalEnergy（Flux Networks / Draconic Evolution）**：两 API 反射装配（LinkageError 降级为"FE 仍可用"警告）；Flux 受 `enableFluxNetworksIntegration` 配置门禁（disabled 时 Handle 给空、find 跳过）；`find` 优先 long 能力避免 FE 门面与 long 视图双通道输出；`modifyEnergyStored` 处理 `Long.MIN_VALUE` 取反溢出；`External` 的 stored/capacity 负值归零。
- **MagicHatchBlockEntity 生命周期**：menu 六值 24 字传输（decode 有 `Double.isFinite` 防 NaN/Inf 注入）；invalidate/revive 成对；serverTick 对 AURA/WILL 每 5 tick 强制显示同步（环境量会自己变）；machineColor 独立走 UPDATE_CLIENTS。
- **Jade**：插件类两侧加载但本类只引服务端类型（客户端 provider 仅在 registerClient 引用）；能量走 long `EnergyAccess` 视图并覆写文本（Flux/DE 大数不被 FE int 截断显示）；控制器的状态/进度/owner/并行由服务端 `appendServerData` 采集（E9）。
