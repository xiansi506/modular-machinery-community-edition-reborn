# P03-a：机器定义来源、覆盖与同步

基线：Reborn 0.121.0、协议 12，Git HEAD `f94ba299e37f0975ac5255f90671f990bacfc61a`。本子批次检查机器声明扫描、配置/数据包/脚本覆盖、注册表与客户端同步；字段规则、配置配方和完整游戏重载留待 P03 后续子批次。未改业务代码或启动游戏。

## 发现

### P03-01：机器声明可与内置控制器注册名冲突（P1，启动风险）

**触发：** 在配置机器目录添加 `{"registryname":"machine"}` 或 `{"registryname":"factory"}` 并重启。声明扫描将名字转成 `machine_controller` 或 `factory_controller`，而模组已用这两个名称注册通用控制器；生成的专属控制器随后进入同一个 Forge 注册表。带有机器工厂控制器的名称与其他机器的普通控制器也可能产生相同后缀名。

**证据与限制：** 实际 `MachineDirectory.scanMachinePaths` 离线接受这两个声明并生成上述名称；静态核对 `ModBlocks` 注册顺序，以及当前 Forge 的 `DeferredRegister.register`/`RegistryObject.equals` 字节码，重复名称会触发 `IllegalArgumentException`。未运行完整 Forge 启动，因此属于启动调用链确认，实际崩溃报告未采集。涉及配置作者选择名称，不是普通玩家远程触发。

**位置：** `machine/MachineDirectory.java:115-177`，`block/ModBlocks.java:61-109,130,168-187`。建议在预声明阶段对同一注册表的通用、普通、工厂及其他现有名称做统一冲突检查，输出文件与两个来源；避免为了重名悄悄更改已发布方块 ID。

### P03-02：机器引用变量集后，客户端无法重建该定义（P2）

**触发与影响：** 机器的 `parts` 或其他结构位置用 `common_casing` 等变量名，服务端加载时按变量集展开并成功注册，但同步保留的是原始 JSON；客户端 `parseForClient` 以空变量表重新解析，拒绝该定义。结果是服务端存在机器，客户端机器表缺失；依赖客户端定义的 JEI 结构/机器分类及相关显示可能缺少它。服务端加工未在本次测试中验证，不能据此断言机器本身停机。

**证据与限制：** 实际 `MachineSchema.read`、`MachineRegistry.replace`、`MachineDefinitionSyncPacket.snapshot` 和 `ClientMachines.accept` 在同一离线 JVM 中执行：服务端解析成功、客户端拒绝变量定义；使用 `minecraft:stone` 的对照定义可正常客户端解析。无真实网络、JEI 或集成服务器测试。旧版 1.12.2 `MachineLoader` 会先构建变量上下文再解析机器；新旧同步架构不同，不能直接假定旧版的网络时序。

**位置：** `machine/MachineLoader.java:153-180`、`machine/MachineSchema.java:1017-1055`、`network/MachineDefinitionSyncPacket.java:115-116,133`、`client/ClientMachines.java:27-40`。建议同步解析所需的权威变量上下文，或生成保持其他原始字段完整的已展开定义；覆盖普通部件、修饰器、动态段、变量重载和两侧对照，注意协议变更。

P03-c 补充验证了另一种上下文缺失：省略默认并行字段时，同一 JSON 会分别采用两端本地 COMMON 配置，产生不同定义。详见[P03-c 报告](P03-c-配置配方与默认值.md)，仍归本编号，避免重复计数。

### P03-03：同一机器 ID 的来源优先级可能反转（P2）

**2026-10-31升级来源扩展：** [P06-c2b](P06-c2b-升级总线生命周期与重载.md)实际读取审计配置alias.json、数据包表和脚本暂存，复现同一逻辑升级ID的配置×3反压脚本×5；脚本putAll覆盖原数据包键时保留靠前插入位置，后续配置别名获胜。与本条相同的分层来源/逻辑ID顺序根因，沿用P03-03；没有修改用户配置或运行完整Forge重载协调器。

**触发与影响：** 数据包文件 `modular_machinery_reborn:a`、配置目录 `a.json` 同资源路径，另有一个数据包文件 `audit:z`，且二者定义同一个 `registryname`。加载器先按**资源文件 ID**把配置 `a` 覆盖进 `LinkedHashMap`，覆盖不会把该键移至末尾；如果 `z` 排在其后，按机器 ID 放入结果表时，后面的数据包 `z` 会覆盖配置定义。实际胜者受资源迭代顺序影响，与注释承诺的“配置目录优先于数据包”不一致，且没有为这次冲突输出明确覆盖告警。

**证据与限制：** 在隔离配置目录和人工指定顺序的数据包映射下，实际 `MachineLoader.apply` 到达 `MachineRegistry.replace`：配置的石头结构被后面的数据包金块结构覆盖。随后离线进程因 Forge `ModBlocks` 初始化缺少 `net.minecraftforge.fml.common.Mod` 而无法走完加载器尾部；冲突结果已经发生，但不是完整 Forge reload。没有假设真实资源管理器必定以该顺序迭代。

**位置：** `machine/MachineLoader.java:151-180`、`machine/MachineDirectory.java:252-289`。建议分别解析两层，再按机器 ID 明确定义优先级和同层冲突规则；同时保存赢家的来源 JSON 并记录冲突，回归相同/不同文件路径及变量名碰撞。

### P03-04：错误变量文件仍会部分覆盖已有变量（P2）

**触发与影响：** 变量文件先声明合法的 `casing`，后声明一个不合法的字段。`readVariables` 逐项写入共享变量表，遇到后项失败时外层记录该变量集失败，但此前的 `casing` 已覆盖旧值且不会回滚；机器可能按一个被报告失败的文件中的部分内容构成。

**证据与限制：** 直接调用实际私有 `readVariables`：`casing` 从泥土改为石头后，非法数字字段使解析抛错，但变量表中的石头保留；实际 `MachineSchema.read` 随后使用了石头。未运行完整资源 reload。旧版 1.12.2 对一个变量文件先反序列化再将结果放入变量上下文，可作为语义对照。

**位置：** `machine/MachineLoader.java:156-165,300-304`；旧版 `common/machine/MachineLoader.java:132-134`。建议先在临时表校验整个文件、成功后一次合并，并明确单字段错误的错误信息及同名优先级。

### P03-05：注册后修改 KubeJS 构建器会改变客户端同步源（P2，特定脚本写法）

**触发与影响：** 脚本在 `.register()` 之后继续对同一机器构建器调用 `.part()` 等修改方法。服务端已将当时解析出的定义暂存，但 `MachineDefinitions` 同时保留的是构建器持有的可变 JSON 本体；之后的修改只改变同步源，客户端重建出不同结构，而服务端仍使用先前的结构。只有使用这种注册后继续修改的脚本写法才触发，不代表普通链式 `.register()` 都有问题。

**证据与限制：** 实际 `MachineRegistryEventJS`/`MachineBuilderJS` 离线执行：注册时 1 个部件，注册后追加第 2 个部件，服务端暂存定义仍为 1，客户端按暂存 JSON 解析得到 2。未运行 KubeJS 脚本重载或联机。位置：`kubejs/MachineBuilderJS.java:141,579-586,600-601`、`machine/MachineDefinitions.java:100-110`、`network/MachineDefinitionSyncPacket.java:115-116`。建议在暂存时深拷贝来源并禁止注册后继续修改或明确使用新构建器；同步测试应验证两侧的所有结构部件，而非只比较 ID。

## 正向验证与后续

用实际暂存、覆盖、注册表及客户端接收方法，在离线单 JVM 中验证：有源 JSON 的脚本覆盖文件定义；开始新周期后移除脚本可恢复文件定义；删除全部来源后两侧注册表均为空。这个测试没有验证 Forge/KubeJS 的真实事件顺序、失败的整次 reload 或正在加工机器如何处理旧定义。控制器结构检查依赖周期调度，定义替换未见显式触发即时检查；是否存在可观察的过渡行为及在途配方影响留给 P06，不能直接断言资源错误。

离线复现器及日志位于工作区同级 `_audit/code-survey-0.121.0/P03-a/LoadingAuditCheck.java`、`run.py`、`checks.log`。配置目录均为该审查目录下新建的临时测试数据，未写入玩家游戏配置。P03-a 的来源和同步离线勘测已完成，实机待验；P03 整体仍需检查具体 schema、配置配方来源、失败/重载边界及其组合。
