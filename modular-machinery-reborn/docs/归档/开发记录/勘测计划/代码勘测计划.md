## 各部分的检查清单

### P01：创作者工具与导出

- 从使用物品、执行命令、JEI 拖入到服务端落盘，画出真实调用链；区分客户端显示状态与服务端权威状态。
- 检查创造／权限组合、持有物品要求、距离、维度、nonce／revision、窗口关闭、重生／退出／停服及超时后迟到回包。
- 组合检查两点框选、增减、空气过滤、撤销／恢复、材料替换、NBT 筛选、旋转、不可读区块、预览后世界变化；失败时保留数据，成功时不重复导出。
- 验证路径隔离、文件重名、写入中断、大小／嵌套／需求数边界；JSON／KubeJS 使用原生解析链确认等价，包含 long、数组、特殊字符串、中文与高级字段。
- 优化候选包括界面重建、输入保留、资源列表检索、反复深拷贝和大选区遍历；先记录调用次数与数据规模，再判断是否值得改。

### P02：通信与服务端交互

- 列出消息方向、字段顺序和服务端处理入口；检查长度、枚举、ID、数值范围、sender、菜单 ID 与目标方块验证。
- 按普通玩家、创造但无权限、管理员、失效菜单、跨维度和断线重连分别检查；客户端传入的数据不能替代服务端库存、位置和权限。
- 检查重复／乱序操作、滚轮连续修改、页面切换与旧回复；区分“拒绝或断开异常客户端”与“整个服务端崩溃”。
- 优化同步频率和包大小前，先确认变化检测不会遗漏状态，且不会把旧客户端绝对值覆盖新服务端值。

### P03：数据来源与重载

- 核对数据包、配置与 KubeJS 的优先级、同 ID 覆盖、控制器预声明、变量集、未知字段、缺失注册项和错误定位。
- 覆盖新增、删除、改名及失败重载，确认注册表、配方索引、结构缓存和正在加工对象之间的引用处理。
- 检查集成服务器的逻辑两端隔离，及同步尚未完成时的客户端行为；逐项确认旧缓存何时失效。
- 记录解析次数、缓存键、失效条件和磁盘遍历规模，避免用永久缓存掩盖 `/reload` 的正确性问题。

### P04：解析与匹配

- 对所有内置需求类型列出字段、默认值、别名、合法边界及报错；检查从 JSON、KubeJS 和网络进入时是否一致。
- 重点测试负数、零、小数、超 int／long、非常大的指数、空数组、空标签、缺失 ID、输出范围、概率与选择标签。
- 保留传统 NBT 比较／正则模板语义，同时验证 literal NBT 的数字类型、空容器、数组和普通字符串不失真。
- 既有熔炉导入和机器配方复用只查现状，不扩展适配器。解析热点优化应保留错误定位和重载语义。
- 子批次：a 根字段、通用需求元数据、命令和网络往返；b 物品/NBT/原料数组/催化剂；c 流体、气体及能源需求解析；d 魔法资源需求解析；e 修饰符与既有配方适配器；f 数字接口需求与 P04 文件覆盖收口（清单核对补列）。完整资源结算和后端实现仍分别归 P05、P08/P09。

### P05：结算与事务

- 子批次：a 物品/流体共享预留与通用提交/回滚；b 数量、并行、概率及物品特殊支付；c1 能源、c2 气体、c3 魔法事务与精度；d 跨资源组合、异常/回调和文件覆盖收口。按实际规模可继续细分。

- 分别跟踪检查、预留、提交、回滚和实际修改；验证多个需求共享同一仓口、能力或环境资源时不会重复使用同一份资源。

## 统一的证据与风险标准

每条发现使用 `Pxx-序号` 编号，并给出以下信息：

| 字段 | 必须说明 |
|---|---|
| 分类 | 安全问题、功能／数据一致性问题、稳定性问题、性能问题或可维护性建议 |
| 位置 | 基线提交、文件与行号、相关方法和调用链 |
| 触发与影响 | 输入、玩家权限、依赖、运行阶段、复现步骤；预期与实际结果 |
| 证据 | 静态调用链、离线原生执行、GameTest 或实机；写清实际做了哪种 |
| 确认状态 | 已复现／调用链确认／待验证。只有猜测或缺少调用者的情况不写成已确认漏洞 |
| 严重程度 | P0：可触发的灾难性服务端／存档破坏；P1：越权、刷资源、持久数据丢失或关键功能失效；P2：常见功能错误或已证实的明显性能问题；P3：低风险显示／维护建议。按实际触发条件调整，不仅按关键词定级 |
| 建议 | 最小修复方向、可能影响、需要补的验证；优化写明预期收益依据和失效／兼容风险 |

配置和脚本通常来自有权限的作者，C2S 消息与普通玩家操作的信任级别不同。报告必须说明谁能触发，不能把管理员明确授权的导出或脚本执行直接标成越权。

性能结论至少给出调用次数、分配量、复杂度增长或可重复的测量之一。没有证据的改写思路标作候选建议；单纯缩短代码、改名或套用新架构不自动算优化。

## 每次的交付与停止条件

每次勘测按同一格式输出：

1. 本部分／子批次、实际基线、查过的文件和方法，必要依赖与未覆盖范围。
2. 已确认问题按严重程度排序；优化建议另列，待验证线索另列。未发现已确认问题时直接说明，不为凑数编造问题。
3. 最小复现与验证结果，保留输入、日志和参考结果。复用旧夹具前检查是否仍对应当前行为；只检查方法名、搜索次数或新旧函数互相一致不能证明真实行为正确。
4. 推荐修复顺序与仍需实机验证的场景；跨模块线索登记到所属 Pxx。
5. 更新本页对应状态、报告路径和下一部分后停止本轮，不自动开始下一部分。

只有完成本部分约定的入口与组合场景检查、实际文件清单核对、问题／待验证项报告后，才可标“勘测完成”。其中仍有实机待验时写“勘测完成，实机待验”，不写成所有问题已排除。

报告按需集中到本目录的 `勘测/` 子目录；临时复现器和详细日志放项目同级 `_audit/code-survey-<基线或日期>/Pxx/`，不塞入使用教程或主页。仅制定计划不需要构建、升版本或新增回归；后续确实修改代码时遵守[开发注意事项](../../../../../注意事项.md)，验证受影响范围并归档相应版本。
