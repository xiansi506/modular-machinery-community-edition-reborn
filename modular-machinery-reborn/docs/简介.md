## 这是什么

旧版 **Modular Machinery: Community Edition**（1.12.2）在 **Minecraft 1.20.1 / Forge** 上的重实现。

**它是一个框架**：本模组**本身不含任何机器、也不含任何配方**。你的多方块机器与配方由你自己提供，三条路任选：

- **数据包** JSON（推荐，`/reload` 即生效）
- **配置目录** `config/modular_machinery_reborn/machinery/`（**重启后**机器可获得**专属控制器方块**）
- **KubeJS** 脚本（服务器脚本目录，`/reload` 即生效）

详见 [使用说明.md](使用说明.md) 与 [KJS-配方指南.md](KJS-配方指南.md)。

## ✅ 已完成（均已在游戏中验证）

**机器定义**
- 数据包 / 配置目录 / KubeJS 三来源；多层与任意形状的结构；按控制器朝向旋转匹配
- 蓝图绑定机器、`requires-blueprint`
- 控制器声明机制（数据包机器也能有专属控制器）
- **KubeJS 能写完整定义**（0.31.0 起）：`modifiers` / `smart-interfaces` / `has-factory` / `factory-only` /
  `max-threads` / `core-threads` / 三个并行字段 / `failure-action` / `requires-blueprint` 全部有对应方法，
  嵌套项可写对象字面量或 JSON 字符串；校验与数据包**共用同一份 schema**，报错逐字相同。写法表见 [KJS-配方指南.md](KJS-配方指南.md) §六
- **生效时机分得清**：改数据（结构、配方、升级、脚本）**`/reload` 即生效**；**新增一个方块**（专属控制器、工厂控制器）必须**重启**——判据与全表见 [使用说明.md](使用说明.md) §六

**配方引擎**
- 需求列表 schema；需求类型：`item` / `fluid` / `energy` / `interface_number_input` / `ingredient_array_input`
- 流体可**逐 tick** 消耗/产出：在 `fluid` 需求上写 `"perTick": true`（原版那个 `fluid_pertick` 类型在源码里 `createRequirement` 返回 `null`，是死类型，JSON 无入口）
- 开工扣输入、逐 tick 扣能源、完工独立掷概率
- 旧版矿辞写法（`ore:`）映射到标签；旧命名空间（`modularmachinery:`）原样兼容

**仓口与端口能力**
- 物品/流体/能源仓持有存储并暴露能力；按等级切换界面贴图；流体按颜色渲染

**界面（复刻原版）**
- 机器控制器界面（176×213）、仓口界面、工厂控制器界面（280×213）
- **3D 结构预览**：右键蓝图打开；预览面板的**按钮行齐备**（重置视角 / 图层开关 / 逐层 2D 视图 / 层滚动条）；JEI「机器结构」类别；机器信息含并行/线程各行
- 配方 JEI 页面（原料数量、组成机器的原料）
- **每机器一个 JEI 类别**：每台机器各有自己的类别与催化剂（那台机器的控制器 + 绑定到它的蓝图），不是所有控制器共享一个

**升级 / 并行 / 工厂**
- 升级总线 5 级（3/6/9/12/18 槽），升级效果以数据声明
- 并行控制器 5 级（4 / 16 / 64 / 256 / 512），并行上限真实结算 N 份
- 工厂控制器：多条不同配方同时加工、核心线程、线程上限
- 配方修改器（时长/产出/输入/概率/能源）

**智能数据接口**
- 并入控制器（不再有独立方块），供 `interface_number_input` 需求读取

**结构构造工具**
- 右键选区（WorldEdit 棒式）、白色轮廓、按控制器朝向旋转、**导出机器定义片段**到配置目录

**兼容**
- ModularController（旧 MOC）的 `modularcontroller` 命名空间兼容，旧存档控制器不丢，并提示迁移

## ❌ 未完成（尚不可用）

**结构**
- **可变尺寸结构（`dynamic-patterns`）未实现** → 内置机器中**装配线 `assembly_line` 缺席**（旧版 4 台内置机器已移植 3 台）

**配方**
- 气体需求：`gas` / `gas_pertick`（依赖 Mekanism 气体 API）
- 配方适配器（把别的模组的配方机械地接进本机器）

**界面与表现**
- `color` 染色
- `craftcheck.failure.*` 的完整失败文案（等料时只显示 `idle`）

**工具**
- **投影器 `machine_projector`**（世界空间幽灵预览）——本次不做
- **`ItemDebugStruct`** —— **不移植**（所有者决定）：旧版**从未注册过它**、实现也是坏的（见 [剩余项实施顺序.md](剩余项实施顺序.md) §6.1）
- **真正的「圈区域自动摆方块」建造器** —— 旧版**没有**这个功能；本模组的构造工具是「选区 + 导出定义」，不是放置器。**所有者已决定不做。**

**脚本**
- AE2 / GregTech / TConstruct 等兼容模块（**逐个独立可选**，已确认**在项目目标内**；见 [剩余项实施顺序.md](剩余项实施顺序.md) 波 5）
- **旧版 CraftTweaker 脚本能写的东西，本版由 KubeJS 入口覆盖**（**不移植 CraftTweaker 桥本身**）：
  机器定义那半由波 1 的 11 个扩展字段补齐，配方与升级声明那半排在波 5.1。
  已经可用的部分见上面「✅ 已完成」与 [KJS-配方指南.md](KJS-配方指南.md)
