# 安装、目录与重载

**从 0.120.0 及更早版本升级**：同时替换客户端与服务端的 Reborn JAR，再启动游戏。当前协议 12，旧协议无法连接；不要求删除控制器或存档。

适用于 **MMCER 0.121.62 / Minecraft 1.20.1 / Forge / Java 17**，当前通信协议 **13**。多人游玩时，客户端和服务端版本应一致；协议12及更旧版本不能连接，也不是当前配置选项。

**升级至 0.121.10 前先让在途加工完成并备份存档。** 新版将付款记录绑定到配方定义，旧版在途存档没有校验信息，重载时会取消该批次，已付材料按取消规则不返还。新版保存的批次只有在成本、产物、时长、触发布局和机器归属等执行定义一致时恢复；同内容新实例允许恢复，更换同 ID 配方内容会取消旧批次。运行中的执行副本仍按开始时的定义完成，落盘后恢复须通过上述校验。无需删除机器或整个存档。

## 先选需要的功能

JAR 提供机器框架和部件，不自带机器定义与加工配方。第一次使用，从 [圆石加工机](使用说明.md) 和 [可复制示例](../examples/docs-quickstart/README.md) 开始。

| 要做什么 | 需要什么 |
|---|---|
| 只用 JSON 定义和运行机器 | Reborn；练习可先省略能源需求，或另外准备 FE 电源 |
| 浏览加工配方和结构 | JEI；蓝图自身也能打开结构预览 |
| 写服务端／客户端脚本 | KubeJS 6 及其依赖；脚本事件和目录见下表 |
| 使用气体 | Mekanism；只支持气体，不把其他化学品当作气体 |
| ME 物品／流体自动化 | AE2；使用 ME 气体还需 Mekanism 和 Applied Mekanistics 1.4.3 |
| 自定义模型／动画 | GeckoLib 和客户端资源；不写模型不需要它 |
| 魔力、灵气、LP 或意志 | 分别安装 Botania、Nature’s Aura、Blood Magic 3 及其依赖，见 [魔法资源](联动/魔法资源.md) |
| long 能源设备连接 | 按需选装 FluxNetworks 或 Draconic Evolution 及其依赖，见 [能源说明](联动/能源与特殊渲染.md) |

内容用到的方块、物品和资源所属模组也必须存在。只有 JSON 时不需要额外安装 KubeJS；安装某个兼容模组不会自动创建使用它的机器。

## 文件应该放哪里

下表中的 `<实例>` 是本次启动的实例目录，`<世界>` 是正在加载的世界目录。专用服务器应修改服务器对应的文件，不是只修改自己客户端的单人存档。

| 内容 | 路径 | 生效方式 |
|---|---|---|
| 数据包机器 | `<世界>/datapacks/<包名>/data/<namespace>/machinery/*.json` | `/reload` |
| 数据包配方 | 同包内 `data/<namespace>/recipes/*.json` | `/reload` |
| 结构变量集 | 同包内 `data/<namespace>/machinery/*.var.json` | `/reload`；由使用它的结构解析 |
| 配置机器／专属控制器声明 | `<实例>/config/modular_machinery_reborn/machinery/*.json` | 结构数据可 `/reload`；新增控制器方块需两端重启 |
| KubeJS 机器与配方 | `<实例>/kubejs/server_scripts/*.js` | `/reload`；机器事件要 `.register()` |
| GUI、模型和动画回调 | `<实例>/kubejs/client_scripts/*.js` | `/kubejs reload client_scripts` |
| 模型、纹理、动画、语言 | 客户端资源包 `assets/<namespace>/...` | 启用资源包，再按 F3＋T 刷新客户端资源 |
| 仓口容量等通用配置 | `<实例>/config/modular_machinery_reborn-common.toml` | 按对应说明重启世界／重新加载方块；不把 `/reload` 当作方块注册重启 |

数据包根必须直接包含 `pack.mcmeta` 和 `data/`，不要多套一层下载文件夹。1.20.1 示例使用 `pack_format: 15`。结构数据与客户端资源不是同一个包：只把模型放进服务端 `datapacks`，不会自动把纹理发给玩家。

`MachineRegistryEvents.registry` 定义机器，`ServerEvents.recipes` 定义配方，`MachineClientEvents` 修改客户端显示。三个事件不能相互替代；详情见 [配方指南](KJS-配方指南.md) 和 [客户端脚本](进阶/客户端脚本指南.md)。

## ID、优先级与重载

结构里写错或缺少依赖模组的方块 ID 会报错，不能把它当作空气跳过；要留空请显式写 `minecraft:air`。修改后先检查重载日志。工厂在当前已加载实例中持有执行副本的批次，继续使用该副本；下一批重开工会重新读取当前配方，同 ID 修改后使用新定义，已删除或不再属于当前机器的配方不会继续开工。这个说明不保证结构变化、区块重新加载或重启后的任务恢复；修改前先让在途合成完成。

- 机器由 `registryname` 标识，例如 `tutorial:stone_processor`。配方根的 `machine` 必须指向它。
- `data/tutorial/recipes/stone.json` 的配方资源 ID 是 `tutorial:stone`；配方 `registryName` 不会改变文件资源 ID。KubeJS 用 `.id('tutorial:stone')` 设置实际配方 ID。
- 同一机器 ID 同时来自不同来源时，KubeJS 优先于配置目录，配置目录优先于数据包。结构没变时，先检查是否有高优先级同名定义覆盖；不要同时安装等价 JSON 与 KubeJS 示例。
- `/reload` 不会新增已冻结注册表中的方块。专属控制器按 [预声明步骤](使用说明.md) 注册，客户端和服务端都需要对应声明并重启。
- 修改前先让测试机器完成在途合成。删除配方或改其需求不保证旧任务按旧定义续跑；重载也不是退款按钮。

## 建议的排错顺序

1. `/datapack list enabled`：确认修改的是当前世界、包根位置正确。
2. `/reload` 后读 `logs/latest.log` 与 KubeJS 错误：找到第一条解析错误，核对文件路径和完整 ID。
3. `/mm-syntax`：检查磁盘上的机器定义与已加载配方关联。它是诊断命令，**不会应用修改，也不会重新执行 KubeJS 脚本**；修正后仍需 `/reload`。
4. 打开目标机器蓝图／JEI 预览，按控制器朝向搭建；对准控制器执行 `/mm-diagnose`，再检查输入、输出空间、FE/t、红石、标签和输入组。
5. 需要查手中物品及 NBT 时用 `/mm-hand`；不要把显示名称当作注册 ID。上述 `mm-` 诊断／蓝图命令需要权限 2。

报告问题时提供：Reborn 版本、所用可选模组版本、第一条相关错误及堆栈、最小机器／配方文件、实际放置方向和操作步骤。截图能展示症状；结构与配方文本更便于直接复现。

## 0.121.32配置与重载修正

配置配方目录在启动时为空或不存在，也会注册稳定的服务端资源来源；之后加入第一份合法配方可由同一资源仓库的重载发现，删除最后一份也不保留旧资源。变量文件只有整份解析成功才覆盖变量，失败文件的前半段不会部分生效；这不代表整次重载具有事务回滚。

工厂默认线程数和默认是否支持工厂，在新解析机器时读取当前已加载的Forge配置；已解析定义和已付在途批次不据此追溯改写，显式字段仍优先。先确认配置已由Forge实际读入，再重新加载定义；这不会在方块注册冻结后新增工厂控制器。服务端与客户端默认来源不一致、整体重载失败回滚等其他已知问题仍待处理。
