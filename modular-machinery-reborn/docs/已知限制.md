## 一、绝对不做（刻意的设计决定，**不是缺陷**）

| 项 | 为什么 |
|---|---|
| **智能数据接口的「字符串」类型** | 旧版枚举里**只有 `NUMBER` 一个常量**，全原版唯一读取者是数值输入，其两个字段是 `float`。**没有任何东西能读字符串**——所以不做，而不是"还没做"。 |
| **智能数据接口不移植为独立方块** | 并入控制器（D16）。旧版里它是独立方块，但**控制器本来就是唯一读取入口**，所以搬迁后**访问路径一字未改**，消失的只是一个中间方块。 |
| **工厂不做真异步** | 旧版自己的类注释就写着「不是真正意义上的线程」，代码也支持——它是「独立进度条」，不是线程池（D15）。 |
| **`catalyst` 不作为需求类型** | 旧版**根本没注册它**（没有类型 id）、JSON 读取器返回 `null`，唯一构造入口是 CraftTweaker。它的真实行为是**结算路径上的「修改器来源」**，属另一种机制。 |
| **`item_durability` 不作为需求类型** | 旧版这个类型是桩（`createRequirement` 返回 `null`、**全仓库零实例化**）。**耐久消耗本身在原版是完整实现的**，但挂在 `item` 需求的一个字段上，且**唯一写入者是 CraftTweaker**——原版**没有任何 JSON 字段名**。 |
| **`factory-only` 对数据包定义不生效** | 方块集在定义加载前就冻结（D8 约束），只解析并告警。 |
| **异步工厂、真正的线程池** | 同上，不做。 |

## 三、配置键里有一个「不起作用」的——**这是有原因的，不是 bug**

`general.modular-controller-compatible-mode`（默认 `false`）在原版里用来**控制是否注册 MOC 兼容方块**。**在 1.20.1 上这个控制不可能存在**：

- Forge 的加载顺序里，**注册表事件排在配置加载之前**（`LOAD_REGISTRIES` → 之后才是 `CONFIG_LOAD`），所以注册期读不到配置值；
- 而方块 id 是**存档反序列化的依据**——**id 不存在，世界根本打不开**，所以"先开开关再进旧世界"在原理上不成立。

因此 **MOC 兼容方块始终注册**（代价：多出一些注册项，**对策是这些物品不进创造模式标签页**，全新安装的可见面不变）。这个键**保留以兼容旧配置**，它的**注释里就写明了它在本版无效**——而不是留一个撒谎的注释。

`general.disable-moc-deprecated-tip`（默认 `false`）**是真开关**，用来关掉旧控制器上的迁移提示。

## 五、机器与配方的来源

**jar 内不含任何机器或配方**（内容外置，刻意如此）。机器的来源是：

1. **数据包**（推荐，可 `/reload`），示例见 `example-datapack/`；
2. **配置目录** `config/modular_machinery_reborn/machinery/`（作者机器在启动期扫描，因此也能拿到专属控制器），示例见 `examples/`。

**配方**同样来自数据包（另有 `config/modular_machinery_reborn/recipes/**`）。

> **发布时的内容分发方式已决定（0.30.0）：仅文档引导——什么都不随包分发。** jar 内 `data/` **保持为空**，
> **不附带示例数据包**（`example-datapack/` 只留在仓库里作参考）。
> **于是「文档就是分发方式」**：从空实例到一台能跑的机器与一份配方，全部步骤、
> 完整可粘贴的机器定义与配方，都在 **[`使用说明.md`](使用说明.md)** 里。
> 代价说清楚：**读者没有文档之外的东西可用**——这也是本文与它把「做不到什么」写得这么细的原因。

## 六、建造选择工具（0.29.0）：它导出的是**片段**，不是一份机器定义

**给包作者的三句话：**

1. **怎么写**：创造模式 + 有命令权限（OP）。手持「建造选择工具」**右键**要收录的每个方块 → 该位置加入选区（**再右键一次取消**，白色线框会亮）。最后**右键那台机器的控制器** → 工具把选区导出成一个 JSON 文件，放进
   `config/modular_machinery_reborn/machinery/`，文件名是 `machine-<你的名字>-<年-月-日_时.分.秒>.json`（**同一秒内再导出一次会追加 ` (0)`、再下一次 ` (1)`**，与你点了几次无关：旧版的计数器从 0 起）。
2. **它写了什么**：**只有 `parts` 一个字段**，每个位置一项，形如
   `{"x":1,"y":0,"z":0,"elements":["modular_machinery_reborn:blockcasing[casing=reinforced]"]}`；坐标是**相对控制器**的；若那个位置是方块实体（仓口、控制器…），还会多一个 `"nbt"` 字段（其 `x`/`y`/`z` 已被去掉）。
   **方块的每个状态属性都会写出来**，所以「当时那个机箱变体」会被逐字记录下来（1.12.2 写的是 `方块@meta`，1.20.1 没有 meta）。
3. **下一步必须自己做**：**文件里没有 `registryname`，所以加载器会拒绝它**（日志里会有一条 `Missing required field 'registryname'`，**这是预期的**，不是报错要你修工具）。把它的 `parts` 数组**粘进你自己的机器定义**，并给那份定义写上 `registryname` / `localizedname`，它才是一台机器。工具写出文件时会**在日志里提示这一步**。

**朝向怎么处理**：导出时工具已经把结构**转成「控制器朝北」的样子**——控制器朝北不动，朝东转 1 次、朝南 2 次、朝西 3 次（每次 90°，方向与加载器自己的旋转一致）。**所以你不需要手工旋转**：把片段填回定义、控制器随便朝哪一面都能成型。若控制器本身也在选区里，它对应的是 `(0,0,0)`，这一项在加载时会被自动跳过（控制器不属于结构）。

**两个已知的取舍**：

- 选区**没有大小上限**（旧版也没有）。片段很大时工具**只在日志里警告**，不拒绝——要导出一整面墙是允许的。
- 选区里有**区块已经卸载**的坐标时，那些位置会被**跳过**并在日志里报出数量（本项目不让读方块顺带加载区块）。旧版会把区块加载出来读成空气。
- **投影器（`machine_projector`）与预览面板的按钮行本次发布不做**（所有者决定）；世界里「半透明幽灵」的显示由**蓝图**提供，不在本工具里。

## 六、哪种来源的机器能拿到**专属控制器**（最常踩的一格）

方块**只能在模组构造期注册**（本项目 D8 约束），所以「有没有专属控制器」取决于**机器定义放在哪里**：

| 定义放哪 | 专属控制器 | 用哪个控制器 | 生效时机 |
|---|---|---|---|
| **配置目录** `config/modular_machinery_reborn/machinery/` | ✅ **有** | `<注册名>控制器` | **需要重启游戏**（构造期扫描） |
| **数据包** `data/<命名空间>/machinery/` | ❌ 没有 | **通用**机器控制器 | `/reload` |
| **KubeJS 脚本** | ❌ 没有 | **通用**机器控制器 | `/reload` |
| 数据包定义 **+ 控制器声明** | ✅ **有** | `<注册名>控制器` | **需要重启游戏** |

### 什么是「控制器声明」

在**配置目录**里放一个**只写 `registryname`、不写 `parts`** 的 JSON：

```json
{ "registryname": "my_machine" }
```

它的作用是**在构造期占住一个控制器方块**，而**定义本体仍留在数据包里**（因此仍可 `/reload`）。这是本项目对旧版「数据包机器拿不到专属控制器」的解法（D10）。

### 用构造工具导出之后怎么办

工具写出的文件**落在配置目录**，而且是**片段**（只有 `parts`）。补上两个字段：

```json
{
  "registryname": "my_machine",
  "localizedname": "我的机器",
  "parts": [ ... 工具导出的内容 ... ]
}
```

然后**重启游戏** → 会出现 `my_machine控制器`。**之后改 `parts` 只需 `/reload`，不用再重启。**

> **文件名不影响任何东西**——决定机器身份的是文件里的 `registryname`。工具生成的 `machine-<玩家>-<时间戳>.json` 只是个不冲突的默认名。

### 排除故障：写对了却没有控制器？

1. 文件**确实在配置目录**（不是数据包目录）；
2. `registryname` 拼写正确、**在重启前**就已存在；
3. **真的重启过**（`/reload` 不够——方块注册只在启动时发生）；
4. 看日志：构造期会打印注册了几个控制器方块。
