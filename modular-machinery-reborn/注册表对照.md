# 注册表对照：旧版 1.12.2 → Reborn 1.20.1

> M0 验收物。对照双方注册真源逐项核对，用于冻结注册名、避免后续改动漂移。
>
> 旧版真源：`_mmce-src/.../common/registry/RegistryBlocks.java`、`RegistryItems.java`、`common/lib/BlocksMM.java`、`ItemsMM.java`
> 新版真源：`src/main/java/com/reborn/modularmachinery/block/ModBlocks.java`、`HatchKind.java`、`HatchTier.java`、`item/ModItems.java`
>
> 对照版本：旧版 MMCE 2.3.2 / 新版 Reborn **0.5.0**

## 1. 结论摘要

| 项 | 旧版 | 新版 0.6.0 |
|---|---|---|
| 无条件核心方块 | 13 | 8 |
| 物品（非方块） | 4 | 6 |
| 条件方块（按模组） | 26 | 0 |
| 按机器动态注册方块 | 有（每机器 1~3 个，默认开启） | 有（3 台内置机器各 1 个绑定控制器，0.9.0；数据包新增机器用通用控制器） |
| 仓口等级表达 | BlockState `size` 属性 + 物品 metadata | BlockState `size` 属性 + 每级一个 BlockItem |
| 仓口方块数 | **每家族 1 个** | **每家族 1 个** |
| 机箱表达 | BlockState `casing` 属性 + 物品 metadata | BlockState `casing` 属性 + 每变体一个 BlockItem |
| 机器结构来源 | 数据驱动 JSON（`parts[]`） | **数据驱动 JSON（`parts[]`）** |

**0.5.0 的关键成果**：把 0.4.x 自创的「一方块一等级」模型退回旧版的「一家族一方块 + `size` 属性」，方块数从 52 降到 7，同时 46 个等级 BlockItem 的注册名保持不变。这是复刻原版 GUI 的前置条件（原版 `inventory_<tier>.png` 恰好 7 张）。

**0.6.0 的关键成果**：机器结构从写死的「同层 3×3 八格环」改为**数据驱动**，与旧版重新对齐；顺带补迁 `blockcasing`（内置机器直接与间接都依赖它）。

### 2.4 按机器动态注册（旧版核心机制，默认开启）

`RegistryBlocks.java:398-441`。若 `Config.onlyOneMachineController`（默认 **false**）为真，**整段跳过**；否则对每台已加载机器注册：

| 方块 | 注册名 | 条件 | 代码位置 |
|---|---|---|---|
| 机器控制器 | `<机器注册名路径>_controller` | 非 `factory-only` | `BlockController.java:89-90`、`RegistryBlocks.java:435-439` |
| 工厂控制器 | `<机器注册名路径>_factory_controller` | `has-factory` 或 `enableFactoryControllerByDefault`（默认 false） | `RegistryBlocks.java:423-429` |
| MOC 兼容控制器 | `modularcontroller:<机器注册名路径>_controller` | `mocCompatibleMode`（默认 false） | `BlockController.java:94-99`、`RegistryBlocks.java:408-420` |

- 机器清单来自 `MachineRegistry.getWaitForLoadMachines()` 加上脚本 `MachineBuilder.PRE_LOAD_MACHINES`（`RegistryBlocks.java:402-406`）。
- 映射表：`BlockController.MACHINE_CONTROLLERS` / `MOC_MACHINE_CONTROLLERS`、`BlockFactoryController.FACTORY_CONTROLLERS`。
- 每台机器的控制器会**各自复制一份 `block_machine_controller.json`**（`RegistryBlocks.java:508-546`），并按机器的 `color` 字段动态染色（`BlockController implements ItemDynamicColor`）。
- 显示名为 `%s Controller`（`tile.modularmachinery.machinecontroller.name`）。
- MOC 兼容模式存在的目的是「防止旧存档不兼容」（`Config.java:102` 注释），并带一条弃用提示。

| 变化 | 内容 |
